## HOW IT WORKS

1. **Log composer.** Type `/email to Hitomi. Dinner at 8?`. A `MAIL:` block previews recipient + body.
   Send with **Cmd/Ctrl+Enter** or the **Send ✉** button (touch). On success the command line in the log
   is replaced by `✉ MAIL → Hitomi Tanaka: Dinner at 8?`, so the log keeps a record.
2. **Grammar.** `/email|/mail to <Name>[.,:;—] <body>`. Recipient is the first word, or two words
   when a delimiter closes them (`/email to Hitomi Tanaka: ...`). Body may be multi-line, max 2000 chars.
   Parser: `src/shared/utils/mail.ts`.
3. **Server.** `POST /api/mail` resolves recipient by `toUserId` (Cohort) or by first/full name
   (case-insensitive, excludes self and `suspended`). Ambiguous names return 409 listing full names.
   Rate limit 20/hour. Writes a `mail_sent` Log event (feeds the intention engine like DMs).
   `GET /api/mail` returns inbox+sent (latest 100 rows) and unread count. `POST /api/mail/read` marks read.
4. **Sync.** New `Mail` component renders above the chat on the Sync tab. It shows for every member,
   including those without chat access (chat gate now only hides the chat). Live updates via SSE `mail`,
   plus a 60s poll fallback. Click a received mail to mark it read; Reply prefills compose.
5. **Cohort.** `CohortConnectWidget` "Send message" became "Send mail": it sets `stores.mailComposeTarget`
   and navigates to Sync, where compose opens with the matched member selected (by id, no name ambiguity).
6. **Privacy.** SSE `mail` events are written only to the connection whose user is the recipient.
