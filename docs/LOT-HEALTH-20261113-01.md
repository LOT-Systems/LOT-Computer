### TypeScript Config Deprecations — LOW SEVERITY

Two deprecated `tsconfig.json` options will break in TypeScript 7.0:

| Option | Warning |
|--------|---------|
| `baseUrl` | `TS5101: deprecated, stops working in TS 7.0` |
| `moduleResolution: "Node"` / `"node10"` | `TS5107: deprecated, stops working in TS 7.0` |

**Impact**: None today — `skipLibCheck: true` keeps builds healthy. Will become a hard
error when the project upgrades to TypeScript 7.x.

**Fix**: Add `"ignoreDeprecations": "6.0"` to `compilerOptions` to silence warnings
and explicitly document the future migration path.

## 6. SYSTEM CHECKS (SERVER-SIDE LOGIC)

Based on `public-api.ts` health check logic, the following checks run on every status call:

| Check | Mechanism |
|-------|-----------|
| Database stack | `sequelize.authenticate()` |
| Engine stack | Weather API ping + React bundle existence + Node ≥ 18 |
| Authentication engine | Session model + Resend API key + manifest file |
| Admin | User model + `/us` page bundle |
| Settings | User model + app bundle |
| Sync | LiveMessage model |
| Memory Engine | Answer + Log models + Anthropic API key |
| Systems | Config loaded + node_modules + package.json + server build |

All checks are gated behind a 2-minute cache. This is well-designed.

**Note**: `checkWeatherAPI()` is named "Engine stack" in the response — the name is
slightly misleading since it also checks the React bundle and Node version. Consider
renaming to `"Core stack"` or `"Runtime stack"` for clarity.
