## How it works
1. In Log type `/email to Hitomi. See you Friday.` → block shows `TO HITOMI — N chars. CTRL+ENTER TO SEND`.
2. Ctrl/Cmd+Enter → `POST /api/emails {to:"Hitomi", body}`. Recipient resolved by case-insensitive first name; 404 if unknown, 409 with candidates if ambiguous, 400 if self.
3. Server stores, emits SSE `email`; recipient's Sync inbox refreshes. Subject = first line of body (≤120).
4. Community (cohort matches) uses `toUserId`, so no name ambiguity — this is the "Cohort Dating" entry point: match → Email → their Sync.

## Decisions / limits
- Internal LOT mail only (no SMTP). Max body 5000 chars.
- "Cohort Dating" had no existing code in the repo; implemented as Community match → Email, not a separate feature.
- Log text is left intact after sending; duplicate send of identical text is blocked client-side.
- Chat messages and email are separate tables; Sync merges them in UI only.
