## DESIGN DECISIONS

```
D1  NOTHING SENDS ON AUTOSAVE. Log autosaves every 7s; a half-typed
    "/email to Hit" must never transmit. Sending is an explicit act
    (Ctrl/Cmd+Enter or Send). Autosave of a draft is harmless.
D2  DRAFT STAYS PRIMARY. Autosave normally pushes the entry down after 7s;
    an unsent /email draft is exempt so the composer never disappears
    mid-thought. After send, the receipt pushes down normally.
D3  RECEIPT REPLACES COMMAND. Prevents double-send on reload and leaves a
    permanent record in the operator's Log.
D4  ONE TABLE. LOT® Email = direct_messages.kind = 'email'. Existing DM
    threads (/dm/:userId) keep working and now show both kinds.
D5  NO FETCH FOR COHORT TAGS. Cohort IDs are read from the react-query cache
    (getQueryData) — the expensive /api/cohorts analysis is never triggered
    by mail.
D6  PRIVATE SSE. Events go only to sender and receiver connections.
```

## DISCOVERIES — LATENT BUGS FIXED

```
B1  direct_messages TABLE NEVER MIGRATED. The DirectMessage model and
    /api/direct-messages routes existed, but no migration created the
    table. The migration creates it when missing (idempotent) before
    adding kind/readAt.
B2  direct_message SSE NEVER DELIVERED. The server emitted the event but the
    /api/sync switch had no case for it, so DM threads never updated live.
    Now forwarded to the two participants only.
B3  LOG AUTOSAVE RACE (data loss). Any immediate save within 7s of typing
    (/prayer, /story, and now /email send) was followed by the stale debounced
    value being saved. When that value was "" the server DELETED the entry.
    Reproduced in browser: receipt PUT, then PUT text:"" → entry gone.
    Fix: autosave skips when the debounced snapshot ≠ current text.
```
