ARTIFACT:        S-2 request: "Design, develop, and deploy the simplest LOT
                  Email system in LOT style. Compose a message in Log with a
                  command '/email to Hitomi.' New messages appear in Sync.
                  Incorporate with Lot Chat (Sync) and Cohort Dating through
                  LOT Community. Push a full .MD report after each session."
CLASSIFICATION:  ENGINEERING
ACTION TAKEN:    Explored the live repo (Sequelize models, Fastify routes,
                  React client) rather than assuming an architecture. Found the
                  system already has 90% of this feature built as disconnected
                  parts: a `DirectMessage` model + `/direct-messages` route +
                  SSE `direct_message` channel (the real "Sync"/"Lot Chat"
                  delivery pipe), a client-side Log slash-command framework
                  (`logTriggers.ts` + a dispatch switch in `Logs.tsx`) already
                  running `/qi`, `/prayer`, `/story`, etc., and a Cohort Connect
                  widget ("LOT Community") whose "Send message" button was a
                  stub that did nothing but switch tabs.
                  Built LOT Email as the missing connective layer, not a new
                  subsystem: a server endpoint that parses "to <Name>", resolves
                  the recipient by firstName, and reuses the exact
                  DirectMessage-create + SSE-emit + Log-record path
                  `/direct-messages` already uses — so a LOT Email is, on the
                  wire, indistinguishable from any other Sync message and
                  needs no new inbox UI. Then wired the Log command and the
                  Cohort Connect "Send message" button onto that one path, so
                  Log-composed and Cohort-initiated messages share one engine.
                  NOTE: "Cohort Dating" does not exist in this codebase as a
                  romantic-matching feature — what exists is behavioral cohort
                  matching (shared journal/log patterns, `CohortConnectWidget`).
                  No dating profiles, swiping, or matching algorithm were
                  invented to fill that gap; inventing one was judged out of
                  scope for "simplest" and was not requested with enough
                  specificity to build safely unattended. The existing cohort
                  widget was instead wired into LOT Email as the closest real
                  analog and the natural integration point once "Cohort
                  Dating" is scoped as its own artifact.

WHAT EACH DOES:
- api.ts: new `POST /lot-email` {recipientName, message} -> resolves User by
  firstName (case-insensitive, excludes self, rejects 0 or 2+ matches),
  creates a DirectMessage, emits `sync.emit('direct_message', ...)` (same
  event DirectMessageThread already listens for), and records a
  `Log` row (`event: 'lot_email_sent'`) mirroring the existing
  `direct_message_sent` pattern.
- queries.ts: `useSendLotEmail` mutation hook against `/api/lot-email`.
- logTriggers.ts: new `lot-email` trigger (keyword `email`) and a pure
  `parseEmailCommand(text)` parser for "/email to <Name> <message>",
  reusable by both the client dispatch and (in principle) any future
  server-side parse point.
- Logs.tsx: wires the `lot-email` trigger into the existing detect-and-
  dispatch effect (same shape as `/qi`, `/prayer`), a result panel
  ("LOT EMAIL: Transmitting... / SENT / error"), and a `/email to <Name>
  <message>` line in the `/system` help screen.
- CohortConnectWidget.tsx: "Send message" on a cohort match now opens
  `/dm/<userId>` (the DirectMessageThread — same Sync/Lot Email pipe)
  instead of just switching to the Sync tab and doing nothing.
