DOCTRINE CLAUSE (folded this session):
  (1) `git push --follow-tags` pushes only ANNOTATED tags reachable from the
  pushed ref; a lightweight tag (`git tag NAME`, no `-a`) is silently
  skipped — the push still reports success. Always create benchmark tags
  annotated (`git tag -a NAME -m "..."`) to match the existing lattice and
  to make --follow-tags actually carry them.

  and reject `refs/tags/*` pushes with a 403 even though the branch push
  itself succeeds. STEP 07 must verify tag presence on origin with
  `git ls-remote origin refs/tags/<tag>` — not just "no error from git
  push" — before a report claims `PUSH: ... PUSHED` for a tag. If the tag
  push is rejected on a scoped credential, record it as
  `TAG: LOCAL ONLY — push rejected (403, credential scope)` and leave the
