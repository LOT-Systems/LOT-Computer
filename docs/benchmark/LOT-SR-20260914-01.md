/SIL WIRED (Logs.tsx)
  New trigger handler for 'sil-check' (logTriggers.ts already declared it —
  dead code until now). Reads intentionEngine's recognizedPatterns for
  pattern 'signal-silence' (QIE P51: 48h quiet after 3+ active sources,
  15+ total signals). Distinct from the pre-existing /silent command, which
  only reports raw hours-since-last-signal with no pattern awareness — the
  two were colliding in intent (both under a "SIL" label) without either
  fully doing what /sil's own doc-comment promised. Rendered under a new
  "SIL-CHK [P51]:" block, separate from /silent's "SIL [PROTOCOL]:" block
  so an operator can tell them apart.

/STORY PERIODS (api.ts, Logs.tsx, queries.ts)
  /story alone: unchanged behavior (last 200 logs, no date filter).
  /story day|week|month|year: filters logs to that window (Op.gte cutoff),
  scales the sample size fed into the prompt (5/10/15 entries at recent/
  month/year), scales completion token budget (512/640/768), and rewrites
  the system prompt's compression instruction per period (STORY_PERIOD_
  GUIDANCE table — a day is "one paragraph, same-day mirror," a year is
  "seasons and turning points, not individual days"). Response and log
  metadata now carry `period` so the client can label the output block
  (📖 [WEEK]) and the operator can tell what scale they got.
  This directly answers the directive's "compressed story of your day/
  week/month/year" — previously only a template-based Sunday weekly cron
  (Job 24, scheduled-jobs.ts) existed at a non-day scale; /story now covers
  all four scales on demand, AI-generated, Usership-gated (unchanged gate).

LOOP CLOSURE (memory.ts, api.ts)
  formatLog() gained a `case 'generated_story'` — without it, per the
  existing Widget-Memory Compression Loop doctrine clause, any /story log
  is fetched into buildPrompt()'s logs array but returns '' and vanishes
  silently. Now it surfaces as "Story: <text>" or "Story (week): <text>"
  in future Memory Engine prompts, so the AI's next questions can build on
  what it told the operator before — literal reading of the directive's
  "further compress the loop, understand the person."
  displayableEvents (GET /logs) gained 'generated_story' — it was omitted
  from the whitelist (unlike its sibling 'lot_ai_story' from the weekly
  job), so every /story record was invisible in the Log tab's own history
  and any admin view. Same failure class, second occurrence this session.
