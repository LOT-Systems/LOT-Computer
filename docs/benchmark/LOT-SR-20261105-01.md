# LOT-SR-20261105-01 — LOT® Email v1

**Date:** 2026-11-05 · **Branch:** claude/determined-turing-71dote · **Type:** FEATURE

## Brief
Simplest LOT® Email: compose in Log with `/email to Hitomi.`, new mail appears in Sync, integrated with Lot Chat (Sync) and Cohort Dating via LOT Community.

## Design (3 moving parts)
| Part | Where | Behaviour |
|---|---|---|
| Compose | Log (`Logs.tsx`, `parseEmailCommand` in `logTriggers.ts`) | `/email to Hitomi. body…` shows an `EMAIL: TO HITOMI` block with Send. Nothing is sent while typing; Send is explicit. Body = log text minus the command. `/email to First Last:` supported. |
| Transport | `POST /api/emails`, `GET /api/emails`, `POST /api/emails/:id/read`; `emails` table (migration `20261105120000_add-emails.cjs`, model `email.ts`) | Recipient resolved by first or full name among LOT Community members only (Admin/R&D/Usership/Onyx/Legacy — same gate as Sync chat). 404 unknown, 409 ambiguous (returns candidates). Body capped 5000 chars. |
| Inbox | Sync (`Sync.tsx`) | `INBOX · N NEW` section above chat, latest 10, click marks read. Live via private SSE `email` event (delivered only to the recipient's stream; SSE switch is whitelist-based so no leak). |

## LOT Community / Chat / Cohort Dating
- Chat: inbox lives inside Sync next to Lot Chat, same access gate, same SSE channel.
- Community: both sender and recipient must hold a community tag.
- Cohort Dating: cohort matches are community members, so `/email to <match first name>.` works for them today. **Not done:** a one-click "Email" button on `CohortConnectWidget` matches (currently "Send message" → Sync) and `/email to cohort`. Proposed next.

## Verification

- NOT verified: migration run against a DB, end-to-end send in a running app (no DB/session in this environment). Run `npm run migrate` (or the deploy migration step) before use.

## Known limits
- No subject, threading, attachments, reply, or delete (deliberately minimal).
- Name collisions require full name. Unread count not yet surfaced in the nav/badge.
- Command is left in the log text after sending (log stays as a record).
