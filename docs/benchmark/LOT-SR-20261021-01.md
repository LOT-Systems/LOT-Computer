--------------------------------------------------------------------------------
DESIGN (simplest thing that works)
--------------------------------------------------------------------------------
COMPOSE   In a Log entry type  /email to Hitomi.  The closing period completes
          the command, so a half-typed name never fires. Text written after the
          command is the body. A MAIL block appears under the log with TO, the
          body preview and a Send button. First name or "First Last" accepted.
STORE     New table mails (id, senderId, receiverId, body, readAt, timestamps).
          Separate from direct_messages because mail needs read state.
API       GET /api/mail          inbox + sent (100 each) + unread count
          POST /api/mail         send by toName (Log) or toUserId (cohort/reply)
          POST /api/mail/read    mark one inbox message read
          Errors: 404 unknown name, 409 ambiguous name (candidates returned),
          400 blank or self. Body capped at 4000 chars.
DELIVERY  SSE event "mail", written only to the receiver's stream.
SYNC      MailBox renders at the top of Sync: unread tag, inbox rows, click to
          open + mark read, Reply box. Visible to users without chat access too.
COHORT    Cohort Connect "Send message" became "Send email": hands the member to
          Sync through stores.mailDraftTo and opens a prefilled reply box.
LOG       Each send writes a mail_sent log event for pattern analysis.
