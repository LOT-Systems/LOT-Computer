02 // RELIABILITY DEFECTS FOUND IN THE FOUNDATION
--------------------------------------------------------------------------------
D1  WINDOW LOSS      Widget read entries from GET /api/logs, which is capped
                     at 500 rows. Any active user's calendar entries silently
                     vanished once 500 newer logs accumulated.
D2  TAB UNMOUNT      System tab fully unmounts when inactive, so anything inside
                     CalendarWidget cannot keep time or fire alerts on other tabs.
D3  NO LIFECYCLE     Entries could not be completed or removed — every past
                     task stayed forever, and "upcoming" kept no overdue items.
D4  SECURITY         PUT /api/logs/:id had no ownership check — any signed-in
                     user could overwrite another user's note text by id.

                     (limit 2000), independent of the 500-row Log window. (D1)

                     T-minus / HRS / DTG formatters, 3-pulse alarm tone.
R4 ALERT ENGINE      src/client/components/CalendarAlerts.tsx, mounted once at
                     app root (survives tab switches). (D2)
                       Stage machine per trigger T:
                         WARN    T-15m ≤ now < T      soft banner (timed only)
                         ALERT   T ≤ now < T+30m      overlay + Log + OS notif
                         MISSED  T+30m ≤ now < T+3d   overlay + Log, on return
                       All-day entries muster at 0900 HRS.
                       Entries logged after their own trigger stay silent.
                       Triple dedupe: memory → localStorage (all tabs) →
                       server alertedFor (all devices). One report per trigger.
                       Checks every 5s + on tab-visible + on data change.
R5 ALERT OVERLAY     Bordered panel, top-center, theme colours (bg-bac/acc):

                     Tone plays only when Sound is ON. OS notification when
                     permission granted (requested on first entry add).
R6 LOG INTEGRATION   New event calendar_alert (whitelisted in /api/logs) with
                     stage ALERT | MISSED | DONE | SCRUB, DTG, entry ref.
