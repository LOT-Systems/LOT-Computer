W1 STORY PERIODS     POST /api/story now accepts `period?: day|week|month|
                     year`. week/month reuse the existing
                     generateWeeklySummary()/generateMonthlySummary() (same
                     generators the Sunday/monthly background jobs already
                     run — zero duplication). day/year are new deterministic
                     generators (no AI vendor call, matching the existing
                     week/month convention): src/server/utils/daily-summary.ts
                     (24h window) and src/server/utils/yearly-summary.ts
                     (365d window, rolled up by calendar month). No `period`
                     -> unchanged legacy behavior (Together AI "recent
                     journey" story) — fully backward compatible.
W2 /story CLIENT     logTriggers.ts's existing `/story` keyword regex already
                     matches "/story week" (word-boundary match), so no
                     trigger-detection change was needed. Logs.tsx's
                     story-mode handler now parses an optional trailing
                     day|week|month|year token, strips it from the saved log
                     text, and passes it through to the mutation. The
                     appended result is labelled "📖 [WEEK] ..." etc. so the
                     compression tier is visible in the journal itself.
W3 /system DOC       Added the `/story [day|week|month|year]` line to the
                     in-app command list rendered by /system.
W4 MOMENT SNAPSHOT   System.tsx's Sky and Astrology environment-context
                     blocks (both the free-tier and paid-tier render
                     branches) are now clickable — they create a
                     `system_snapshot` Log via the existing useCreateLog()
                     mutation, reusing the log event that already existed
                     and already renders in Logs.tsx (city/temp/humidity/
                     astro block), previously written only by the automated
                     00:00 UTC job. Server attaches weather+astrology context
                     automatically via getLogContext() at write time — no
                     photo, no audio, matching the "context-only moment
                     record" requirement. A 1.5s inline "Moment recorded ✓"
                     flash confirms the click without a modal/toast. The
                     astrology block's existing view-cycling onLabelClick
                     (Astrology -> Psychology -> Journey -> Biofield) was
                     left untouched; the snapshot trigger is scoped to
                     onChildrenClick and only fires in the 'astrology'
                     sub-view, so it never collides with that cycle.
W5 GITIGNORE FIX     Found and fixed a live infrastructure defect while
                     adding the two new server files: .gitignore had an
                     unanchored `server/` rule (meant, per its own comment,
                     to keep "compiled output" out of the repo — but `dist/`
                     already covers all compiled output). Because gitignore
                     rules only apply to untracked paths, this silently
                     swallowed any NEW file placed anywhere under src/server/
                     while every already-tracked file there (weekly-summary.ts,
                     monthly-summary.ts, etc.) was grandfathered in and
                     invisible to the bug. Removed the dead rule. Left the
                     unrelated `middleware.ts`/`server.ts`/`touch` root-level
                     entries in the same section alone — out of scope, not
                     currently blocking anything.
W6 BADGE/ARCADE HOOK No new badge plumbing added. The compressed period text
                     is appended into the same Log entry the operator is
                     typing in, through the exact code path /prayer and the
                     legacy /story already use — so it is scanned by the
                     existing word-turn/journal-signal system exactly like
                     any other journal content. This was a deliberate
                     "participate, don't bolt on" choice: badges already
                     fire off word count and journal cadence; a compressed
                     narrative landing in the journal naturally feeds that
                     system without a parallel mechanism.
