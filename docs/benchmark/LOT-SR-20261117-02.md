## 4. DECISIONS

| # | Decision | Why |
|---|---|---|
| D1 | Raw SQL, with no Sequelize model | Follows the `agent_ledger` pattern. The table is append-only and a model would invite updates |
| D2 | No text column, enforced in the schema | Privacy comes from the schema, not from a policy. A future caller cannot store text by accident |
| D3 | The closed reason list is enforced in `toCosmoAuditRow` | A bug or a forged verdict cannot write free text into `reasons`, and cannot record CLEARED alongside a real reason |
| D4 | Writes fail soft | The code can deploy before the migration runs. COSMO® still screens; it just does not record yet |
| D5 | `screen` is admin-only and a dry run | No path to a subscriber exists until Node 6 |
| D6 | CASCADE on user delete | The person's trail leaves with the person |

## 6. LEXICON (new terms)

- **Audit row**: a COSMO® verdict reduced to labels: status, reason codes, risk, lead, version, source. Never words.
- **Closed reason list**: the six codes COSMO® may emit. Anything else is dropped before persistence.
- **Dry run (screen)**: an admin tests a draft against a real person's vector. The verdict is recorded, the draft is discarded, nothing is sent.
- **Fail soft**: the audit is optional at runtime. Screening is not.

## 7. DOCTRINE (distilled)

> **Privacy goes in the schema.** If a column cannot hold the text, no future caller can leak it.
