00 // BASELINE (what existed)
--------------------------------------------------------------------------------
CalendarWidget: date-only entries (note/task/call) -> Log event calendar_entry.
No time of day, no alerts, no completion, no cancel. Entries read from /api/logs
(LIMIT 500) so future entries could silently age out of the window.

--------------------------------------------------------------------------------
01 // CHANGES
--------------------------------------------------------------------------------
R1 TIME            Optional HH:mm per entry (native time input). No time =
                   all-day, alerts at 08:00 local.
R2 ALERT ENGINE    src/client/utils/calendar.ts (pure, no React/network).
                   Stages: STANDBY (T-15m) · EXECUTE (T-0) · MISSED (T+30m).
                   Only the LATEST eligible stage fires, so reopening the app
                   after absence gives one alert per entry, not a backlog burst.
                   Entries older than 24h are never alerted.
R3 GLOBAL WATCH    CalendarAlerts mounted at app root (app.tsx): fires on every
                   tab, not just System. 15s tick + focus/visibilitychange
                   catch-up (hidden-tab timers are throttled). Terse banner:
                   "STANDBY // CALL   T-00:15" with [ACK] [DONE]. EXECUTE pulses;
                   MISSED dashed. Optional OS notification + vibrate
                   (widget toggle "System alerts: ON/OFF", permission asked
                   only on click).
R4 LOG AUDIT       Every state change is a Log event, folded into entry state:
                   calendar_entry (id,date,time) · calendar_alert (entryId,stage)
                   · calendar_done · calendar_cancel. Logs.tsx renders them as
                   CAL: STANDBY/EXECUTE/MISSED/DONE/CANCELLED. Server whitelist
                   (displayableEvents) extended.
R5 DEDUPE          Fire-once per entry+stage via localStorage key (written before
                   the POST; shared across tabs) AND persisted calendar_alert
                   logs (survives device change).
R6 RELIABLE FEED   New GET /api/calendar (calendar_* events, 400 days, up to
                   2000) independent of the 500-row /logs window.
R7 WIDGET UI       Minimal list kept. Added time, T-minus countdown, [✓] done,
                   [x] cancel per row. Legacy id-less entries use log id.
R8 TEST            scripts/tests/test-calendar.ts (npm run test:calendar) —
                   13 assertions on stages, dedupe, done, legacy, all-day.
