## 1. BOTTOM LINE

* Widget layer is **structurally healthy**: every widget on the System tab sits behind a `WidgetErrorBoundary` (25 boundaries), every `setInterval` has a matching `clearInterval`, and all heavy polls (SystemProgress 60s, SystemPulse 10s, ContextualPrompts 15s, ChakraErgonomics 2m) already pause when the tab is hidden or another in-app tab is in front.
* **One real lag/pollution defect found and fixed:** `QuantumRandomWidget` ran three timers (1s x2, 10s) with no off-tab gate, re-rendering every second and writing a QIE signal (`recordSignal` -> JSON persist of up to 1,000 signals) at each rollover, even in a background tab. Now gated. (F-1)
* **Widget usage logging did not exist** (only one ad-hoc `cohort_widget_viewed` signal). Added a platform-wide usage ledger at the boundary level plus a daily SITREP-style `widget_usage_report` Log event. (Section 6)
* **Open items, not fixed this push:** 15-month reveal is not implemented as a calendar program (F-4); 40+ widgets ship eagerly in one `app.js` (F-2); chained timers in MemoryWidget lack unmount cleanup (F-3).

## 6. DATA LOG OF WIDGET USAGE (new)

**What shipped**

* `src/client/utils/widgetTelemetry.ts` - bounded ledger (30 days x 80 boundaries) in localStorage; per boundary per day: mounts, first-view, dormant (mounted but rendered nothing), taps, crashes, total/slowest mount ms. Never throws; no network on interaction; debounced 5s write + flush on `pagehide`.
* `WidgetErrorBoundary` - hooks mount time, crash, first-view (IntersectionObserver on the boundary's first DOM node) and tap count (one passive click listener). **No wrapper element**, so layout and flex gaps are untouched. Re-attaches after a crash -> Retry.
* `System.tsx` - 20s after mount, calls `flushWidgetUsageReport`: at most once per 24h (slot claimed before the request so two tabs do not double-post) it posts `widget_usage_report` to `/api/logs`.
* `api.ts` - `widget_usage_report` added to the `displayableEvents` whitelist; `Logs.tsx` - new `WGT-RPT:` handler.
* `window.__LOT_WIDGET_USAGE__()` in the console returns today's summary.

**Log line (military style, instrument readings only; values below are an illustrative example)**

```
WGT-RPT:  25 UP · 0 FAULT · 2 SLOW · 14 TAP
          TOP Planning 5 · Context 4
          SITREP 030348Z NOV 26 · SYSTEM · WX CLEAR SKY · 12C · ONLINE 42
```

The SITREP line **synchronizes context** (Zulu time, weather, users online) into the same Log entry - the "military self-care communications" pattern. `buildSitrep(ctx)` is exported so any interactive widget can attach the same line to its own Log post.

**Granularity caveat:** counts are per `WidgetErrorBoundary`, i.e. per *stack* (Context, Bioethics, Planning...) for stacked widgets and per widget for the singly-wrapped ones. Per-widget granularity inside a stack needs a one-line `data-widget` marker per widget (next push).

**Platform-wide view:** each user's daily report lands as a Log row, so cross-user aggregation is a single query on `event = 'widget_usage_report'` (admin endpoint recommended next, Section 8).
