WHAT CHANGED:
- POST /story now accepts optional period: 'day'|'week'|'month'|'year'. Query
  window narrows via createdAt >= now - N days (1/7/30/365) instead of an
  unbounded 200-row pull. Together AI prompt states the window explicitly
  ("today"/"this week"/"this month"/"this year") so the narrative is scoped,
  not generic. AI-unreachable fallback now runs composePeriodStory() — the
  same dense, template-based, honest-compression tone as Job 24's Sunday
  weekly story (mood tally, self-care count, intention count, one closing
  line) — reused for all four tiers instead of a single flat sentence.
  event=generated_story now carries metadata.period.
- Client: /story day|week|month|year parses the period, labels the response
  block "📖 [WEEK]" etc., and /system's help screen lists all four forms.
- Bug found + fixed while wiring this: the trigger-detection effect only
  fires on a trigger's *first* appearance in the text (set-diff against the
  previous keystroke). Typing "/qi <query>" or "/story <period>" completes
  the bare command token — and fires — before the argument word is typed,
  so the argument was silently dropped on every normal typing flow (only
  a single-paste of the full command worked). Added a 500ms-debounced
  argument-upgrade pass (commandArgValue) that re-checks settled text and
  fires once the query/period differs from what was last processed
  (lastQiArgRef/lastStoryArgRef guard against double-submit on paste).
  This was a latent defect in the already-shipped /qi command, not
  something introduced by this session — fixed as part of the same
  command-argument code path.
