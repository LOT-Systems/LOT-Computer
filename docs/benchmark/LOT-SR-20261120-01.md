## 4. DECISIONS

| # | Decision | Why |
|---|---|---|
| D1 | Aggregate in TypeScript, not SQL | It keeps the logic pure and smoke-testable. The beta is 12 people, so volume is trivial. Capped at 10 000 rows |
| D2 | Privacy floor of 3 people | With one or two people, "beingThere HELD 75%" describes one person's state. Totals stay visible so the admin can tell the surface is alive |
| D3 | Re-filter reason codes on read | The writer already filters, but a hand-inserted or legacy row must not leak text through the read-out |
| D4 | No skip-code writes yet | A baseline would need one row per Memory request. That is a product decision (F9), so it is queued as Node 8 for Vadik |
| D5 | Breakdown by engine version | Weight tuning in Node 7 bumps the version, so before/after reads straight off `byVersion` |

## 6. LEXICON (new terms)

- **Read-out**: the admin aggregate over audit rows. It holds labels and counts, never people or text.
- **Privacy floor**: the minimum number of distinct people before breakdowns are shown (3).
- **Suppressed**: a read-out below the floor. Totals only.

## 7. DOCTRINE (distilled)

> **Measure the voice, never the person.** The read-out counts verdicts. It cannot be turned back into anyone's state.
