05 // WHAT CHANGED
--------------------------------------------------------------------------------
1. /story period arg — `/story day|week|month|year` (bare `/story` keeps
   prior "recent" behavior). Server windows the Log query via Op.gte on
   createdAt (1/7/30/365 days, cap 1000 rows vs. 200 default), widens the
   sampled entries/moods/self-care notes, and the prompt compresses the
   whole window into one narrative (150-300w for month|year, 100-200w
   otherwise), told explicitly to surface highs/lows rather than average
   them away. Response echoes `period` back to the client.
2. generated_story visibility fix — /story has always persisted its output
   as a `generated_story` Log row, but that event was absent from both the
   GET /logs `displayableEvents` allowlist and the Logs.tsx timeline
   switch. The story text the user sees survives as a copy appended into
   their note body, but the dedicated compressed-story record itself
   vanished the moment it left the primary editor — silently defeating the
   "send the compression back so the loop closes" intent. Added the event
   to the allowlist and a `STORY:` / `STORY [PERIOD]:` render case
   matching the existing `prayer_scripture` pattern.
3. /system help text documents `/story [day|week|month|year]`.
4. logTriggers.ts doc-comment updated (detection regex needed no change —
   `/story` already matches `/story week ...`).
