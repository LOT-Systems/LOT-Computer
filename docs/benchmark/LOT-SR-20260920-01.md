WHAT CHANGED, PLAINLY:
- intentionEngine.ts: imports getHourlyZodiac from #shared/utils/astrology
  (previously unused there). Adds Pattern 152 "Circadian Zodiac Affinity":
  buckets the user's last-7-day mood signals by which 2-hour Japanese zodiac
  hour they landed in, scores each bucket (positive − negative) / total, and
  when >=2 buckets have >=2 samples and total mood signals >= 6, surfaces the
  best- and worst-scoring buckets as a pattern (min score gap 1.0 to fire).
  This is the FIRST pattern to read the 'astrology' signal source since it
  was wired as a Tier 0 dependency — closing a real gap, not adding
  decoration. Confidence 0.5-0.8, suggestedWidget 'astrology', timing
  'passive' (never interrupts).
- System.tsx: reads the new pattern via intentionEngine.get().recognizedPatterns
  and, only when present, renders one secondary line under the existing
  westernZodiac/hourlyZodiac/rokuyo/moonPhase summary in the astrology tab.
  Nothing renders when there isn't enough of the user's own data yet — no
  placeholder, no fabricated confidence.
- Logs.tsx: the ASTRO: line in system_snapshot log entries showed only
  rokuyo + moonPhase even though the server (logs.ts) has computed and
  stored all 5 astro fields (western zodiac, hourly zodiac, rokuyo, moon
  phase, illumination %) on every such log since the LogContext type added
  them. Expanded the line to show all 5, in the same order/format the
  System.tsx widget already uses (westernZodiac • hourlyZodiac • rokuyo •
  moonPhase (illumination%)) — this is the literal "synchronize with Logs
  entries" ask: the data already existed server-side, it just wasn't
  surfaced.
- PatternRecognitionWidget.tsx: added 'circadian-zodiac-affinity' to the
  pattern display-name map (P152), matching the existing convention for
  every prior pattern.
- About.tsx: added a "Circadian Zodiac Affinity" subheading under the
  Astrology Widget section, stating plainly what it is (a correlation in
  the user's own logged data), what it isn't (a forecast, a natal chart),
  and that no birth data is collected — consistent with the existing
  "Ambient astrology reading... not a natal chart" comment already present
  in the codebase (shared/types/index.ts, System.tsx).
