05 // ROUTINES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
R1 TIMED ENTRIES     Added optional HH:MM `time` field to calendar entries
                     (native <input type="time">), stored in the existing
                     `calendar_entry` Log's metadata alongside date/text/type.
                     Entries without a time remain valid all-day entries —
                     fully backward compatible with every entry logged
                     before this change. Upcoming-list and day-detail views
                     now render the time (tabular-nums) when present; sort
                     order is date, then time.
R2 ALERT ENGINE      New client-side scheduler (checkAlerts) scans timed
                     entries against dayjs() every 30s, plus an immediate
                     check on mount and on document visibilitychange (tab
                     refocus) so a backgrounded/throttled tab still catches
                     up — same reliability pattern already used by
                     TimeWidget's hourly-chime loop. Two stages per entry:
                     PRE (T-15min) and DUE (0 to -15min window). Each stage
                     fires at most once per entry — de-duplicated via a
                     localStorage-persisted fired-key ledger (30-day
                     retention, pruned on every write) so reloads/re-mounts
                     never re-alert on the same entry.
R3 LOG INTEGRATION   Every alert fired writes a new `calendar_notification`
                     Log row (event + metadata: date/time/entryType/text/
                     stage) — the notification system is itself an audit
                     trail inside the existing Log, not a side channel.
                     Added a matching Logs.tsx renderer (`CAL [ALERT]:`
                     block) so fired alerts read correctly in the Log/
                     Journal view, not just as a toast.
R4 MILITARY TOAST    New CalendarAlertToast: fixed bottom-right panel,
                     border-acc/30 + grid-fill-light (matches existing
                     instrument-grid texture), blinking `[ALERT] UPCOMING`
                     / `[ALERT] DUE NOW` tag (reuses the existing `.blink`
                     keyframe — no new CSS/animation lib added), uppercase
                     tracking-widest primary line, opacity-faded secondary
                     line with tabular-nums time + `SRC: CALENDAR` field
                     tag — same visual grammar as the CONF:/WIN:/SRC:
                     field-prefix convention already used throughout
                     Logs.tsx. Auto-dismisses after 12s or on manual [X];
                     multiple simultaneous alerts queue and display in
                     sequence rather than stacking/overlapping.
R5 STYLE DISCIPLINE  No new dependencies (no toast lib, no animation lib —
                     confirmed none exist in package.json and none were
                     needed). No hardcoded colors — every new element uses
                     the existing text-acc/border-acc opacity-token family.
                     Avoided the EvolutionMilestoneToast anti-pattern of
                     injecting a <style> tag at module load; reused CSS
                     already shipped in index.css instead.
