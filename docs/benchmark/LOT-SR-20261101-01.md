# LOT-SR-20261101-01 — LOT® Email v1 (Log → Sync, via LOT Community)

## Brief
Simplest LOT Email in LOT style. Compose in Log with `/email to Hitomi.` — new messages appear in Sync. Integrate with Sync chat and Cohort Dating through LOT Community.

## Design (simplest thing that works)
No new table, no migration. Email = a `direct_messages` row (existing model). First line of the body is the subject. Inbox = messages where `receiverId = me`.

| Layer | Change |
|---|---|
| Log (`Logs.tsx`, `logTriggers.ts`) | New `email` trigger (`/email`, `/mail`, ✉️) shows a compose hint. `parseEmailDraft()` reads `/email to Name.` + body. **Ctrl/Cmd+Enter** sends, clears the log, shows `EMAIL:` status block. `/system` help lists it. |
| API (`api.ts`) | `POST /api/email {to, message}` resolves recipient by first name (or "First Last") in the community; 404 if unknown; 409 + candidates if ambiguous. `GET /api/inbox` last 50 received. |
| Live delivery | SSE `/api/sync` now forwards `direct_message` to sender/receiver only (it was previously emitted but never forwarded — DM live updates were silently broken). |
| Sync (`Sync.tsx`) | `Inbox` section atop Sync: sender, subject, preview, time, "N new" (seen-marker in localStorage), click → reply in 1:1 thread. Shown even to users without chat access. Live refresh on SSE. |
| Cohort Dating (`CohortConnectWidget.tsx`) | Cohort match button "Send message" → "Email": opens the 1:1 thread with that member (was a dead-end jump to Sync). Replies land in Sync inbox. |
| Types | `SyncEvents.direct_message` added. |

## Verification
- `tsc -p tsconfig.server.json --noEmit`: clean
- `npm run client:js:build`: OK (pre-existing duplicate-key badge warnings only)
- `parseEmailDraft`: header+body, same-line body, empty body → null, plain text → null
- Not run: end-to-end against a live DB (no database in this environment).

## Known limits / next
1. Recipient lookup is by name; duplicates need a last name. Suggest `/email to @handle` or custom-URL lookup.
2. No unread count on the Sync tab label yet; no delete/archive.
3. No subject/threading beyond the existing 1:1 DM thread; no external SMTP (LOT-internal only).
4. Spam/abuse: no rate limit on `/api/email` — add before opening beyond trusted tags.
5. Cohort Dating: could pre-rank `/email to` suggestions from cohort matches.
