DESIGN NOTES:
- `lot_mails` table: fromUserId/toUserId/subject/body/read, indexed on
  (toUserId, read, createdAt) and (fromUserId, createdAt).
- POST /api/mail resolves recipient by first/last name (case-insensitive,
  Op.iLike) — this is what makes "/email to Hitomi ..." work: any LOT
  Community member named Hitomi receives it, no ID lookup needed. 404 with a
  named hint if nobody matches.
- GET /api/mail/inbox, GET /api/mail/unread-count, PUT /api/mail/:id/read.
- SSE: sync.emit('lot_mail', ...) on send; server-side switch filters so only
  data.toUserId === req.user.id ever gets written to a client's stream — same
  per-recipient guard pattern as settings_updated.
- Log trigger 'email-compose' (keywords email/mail, emojis ✉️ ✉ 📧) opens an
  inline compose Block in Logs (To / message / Send-Cancel) instead of trying
  to parse a fully-formed command in one keystroke — the existing /qi-style
  regex-on-fresh-trigger approach only sees the text present at the instant
  "/qi" first becomes a bounded token, which is before most users finish
  typing the query. An inline panel with an explicit Send button reads its
  own field state at click time, sidestepping that timing gap entirely.
  Typing "/email to Hitomi <message>" pre-fills the panel from what's already
  there; the emoji triggers open it empty for manual fill-in.
- Sync.tsx gained a Chat | Mail tab strip (unread count badge on Mail) inside
  the existing canAccessChat gate — no new access tier introduced. EmailInbox
  lists newest-first, click to expand + mark read, live-refreshes via the
  lot_mail SSE listener.
- Cohort Dating integration: ChatCatalystWidget (the "Connect" prompt LOT
  Community uses to suggest a cohort member) gained a secondary "✉ Mail"
  button next to its existing connect action. Clicking it stashes the
  member's name in sessionStorage and routes to Log; Log's primary editor
  reads that key once on mount and opens the compose panel pre-addressed —
  no new global store, no cross-page state machine.
