--------------------------------------------------------------------------------
DESIGN (v1, deliberately minimal)
--------------------------------------------------------------------------------
MODEL     One table `mails`: sender, receiver, subject, body, readAt. No threads,
          folders, attachments, CC, drafts. Inbox/Sent are two views of one table.
COMPOSE   In Log (primary note):
              /email to Hitomi.
              Subject: Tea on Friday      (optional line)
              Message body ...
          A MAIL: block appears under the note: TO / SUBJECT / preview.
          NOTHING SENDS WHILE TYPING (log triggers fire per keystroke; a send on
          that path would mail half-typed names). User presses Send.
          After send the note becomes "✉ Mail sent to <Name>".
RESOLVE   GET /api/mail/resolve?name= — prefix match on first / full name, only
          LOT Community members. One match auto-selects; several -> "Which one?".
DELIVER   POST /api/mail. SSE event `mail` is forwarded ONLY to the receiver and
          carries no body (id, fromName, subject). Sync refetches the inbox.
SYNC      Sync gets Chat | Mail tabs. Mail: Inbox (unread count, underline = unread),
          Sent, expand to read (marks read), Reply, inline composer.
COMMUNITY Scope = Sync-eligible members (Admin, RND, Usership, Onyx, Legacy), not
          Suspended. Enforced server-side for BOTH sender and receiver.
COHORT    Cohort Connect member card gets an "Email" button -> opens Sync Mail
          composer addressed to that member (also records signal
          cohort_email_initiated for the intent engine).
LIMITS    20 mails/hour/sender, body 5000 chars, subject 200, no self-mail.
