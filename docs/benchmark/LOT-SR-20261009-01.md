04 // CONTEXT SYNC -> LOG (weather · time · users online)
--------------------------------------------------------------------------------
Inputs exist: stores.weather, usersOnline, usersTotal, liveMessage, Time/Moon/
Zodiac in System.tsx; server writes `weather_update`, `system_snapshot`,
`user_login/logout` log events. Interactive widgets that POST to the Log:
Planner, Recipe, Calendar, SelfCareMoments (via useCreateLog) + server events
`recipe_viewed`, `benchmark_read`, `intention`, `self_care_*`.
GAP: no widget stamps its entry with a shared context envelope. A log entry from
Planner has no weather/time/online snapshot unless the server adds it. Proposal
(F-08, not built): one `useContextStamp()` returning
{ts, tz, weather, tempC, usersOnline, density, month} appended to
metadata for every widget-originated log, rendered as a compact SITREP-style
line (DTG · WX · NET · STATUS) — terse, fixed-order, acknowledgement word last
(e.g. "Noted."), matching the existing MonthlyPulse dismiss vocabulary.

MONK / LOT AI PURITY: existing basis is good — hideActivityLogs flag, silent-mode
(/silent), freeze-widgets (/freeze), prayer-mode, night-mode, breathe log triggers
(utils/logTriggers.ts). Missing: a per-widget "quiet" preference so a user can
retire widgets (the 41-widget System tab is the opposite of monastic).
