# LOT-SR-20261017-01 — LOT® Email v1

**Date:** 2026-10-17 · **Branch:** `claude/determined-turing-89i358` · **Stage:** PRODUCT · **Status:** GREEN (typecheck clean on touched files, client + server build pass)

## Mission
Design, develop, deploy the simplest LOT® Email: compose in Log with `/email to Hitomi.`, new mail appears in Sync, integrated with LOT Community (Sync chat) and Cohort Dating.

## What shipped
| Layer | Change |
|---|---|
| Command | `/email to <Name>. <message>` typed in a Log. `Ctrl/Cmd+Enter` sends. Parser: `src/client/utils/emailCommand.ts` (first name or "First Last"; separator `.` `:` `,` or newline; separator optional). |
| Log UX | New trigger `email-compose` shows an `EMAIL:` block (hint → SENDING → `SENT → HITOMI · COHORT MATCH (CITY)` or error with candidates). On success the command line in the log is rewritten to `✉ SENT to Hitomi. <message>` (cannot re-fire). `/email` listed in `/system` help. |
| Data | Table `emails` (migration `20261017120000_add-emails-table.cjs`), model `src/server/models/email.ts`, type `Email`. |
| API | `POST /api/emails {to, body}`, `GET /api/emails` (last 50 sent+received, unread count), `POST /api/emails/read {id}`. |
| Realtime | SSE `email` event sent **only to the receiver**, carrying id + sender name, never the body. Sync refetches inbox on event. |
| Sync | `MAIL · N NEW` section above chat: latest 5 received, unread marked `●`, click = mark read. |
| LOT Community | Sender and recipient must both be Sync-eligible (Admin / R&D / Usership / Onyx / Legacy) — same gate as chat. Ambiguous first name → 409 with full-name candidates. |
| Cohort Dating | Send response flags `ARCHETYPE` (same `metadata.archetype`) or `CITY` (same city+country) match; shown in the Log `EMAIL:` block. Deliberately cheap; no pattern-engine call. |

## Deploy notes

2. `src/server/` is matched by `.gitignore` (`server/`); new server files need `git add -f`.

## Findings (not fixed, out of scope)
- `direct_messages` has **no migration** in `migrations/`; the DM feature will fail on a DB built only from migrations unless the table was created by hand.
- SSE switch in `api.ts` whitelists events; `direct_message` is not forwarded, so DM live updates never reach clients.
- `npm ci` fails on peer-dependency conflicts; `npm install --legacy-peer-deps` works.
