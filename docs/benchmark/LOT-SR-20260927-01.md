FEATURE 1 — context_snapshot (click-to-record):
  useContextSnapshot() hook: recordSnapshot(source), 90s-per-source cooldown
  (persistentAtom localStorage), POST /api/logs {event:'context_snapshot'}.
  Server already attaches weather/astro/location via getLogContext() on
  every Log — client only names the source. Wired into System.tsx: Sky,
  Temperature, Sunrise/Sunset, Humidity, Astrology/Biofield blocks, and a
  new TimeWidget onSnapshot prop — additive, alongside each widget's
  existing click behavior (unit toggle, view cycle), never replacing it.
  GET /api/logs already guarantees an empty 'note' log stays the editable
  primary slot regardless of what else gets created, so a snapshot never
  hijacks the field-entry cursor — confirmed by reading the route, not
  assumed. Rendered as a new SNAP: block in Logs.tsx.

FEATURE 2 — journal_follow_up (passive spike detection):
  detectJournalSpike() in journalSpike.ts: pure heuristic (no AI call) run
  once per note-save in PUT /api/logs/:id, guarded by metadata.spikeChecked
  so it fires once per entry. Compares the just-saved entry against the
  user's own last 20 note entries for three pattern types: length_spike
  (2.5x+ baseline word count), intensity_spike (charged-language keyword
  count above baseline — a short, non-clinical list; noticing tone, not
  diagnosing), silence_break (15+-word entry after a 5+ day gap). A match
  creates one gentle line as the NEXT Log entry — found later, never
  mid-typing, matching the passive-Journal design already in place (no
  prompts while writing). Rendered as a new FOLLOW: block in Logs.tsx.
