01b // FEATURE — LOT MAIL
--------------------------------------------------------------------------------
COMMAND:     "/email to <Name> <message>" (also "/mail…", ✉️) typed in Logs.
DETECTOR:    logTriggers.ts — new 'lot-mail' trigger, same idle-until-typed
             convention as /qi, /story, /prayer.
RECIPIENT:   Resolved ONLY against the sender's own Cohort matches (the pool
             CohortConnectWidget already surfaces from LOT Community via
             analyzeUserPatterns/findCohortMatches) — no free-text user
             lookup. This is the Cohort-Dating/Community gate S-2 asked for:
             LOT Mail can only reach someone already surfaced as a match.
DELIVERY:    Two channels per send — (1) an ordinary DirectMessage row (reuses
             existing in-app DM infra, so DirectMessageThread keeps working
             unchanged) and (2) a REAL outbound email via the existing Resend
             integration (sendEmail()) to the recipient's account address.
SYNC:        New sync.emit('mail_sent', {senderName, receiverName, createdAt})
             broadcast — content-free activity line only. Sync.tsx renders it
             as "✉ {sender} sent LOT Mail to {receiver}". The letter itself
             never leaves the DM/email channel — satisfies "new messages
             appear in Sync" without publishing private mail to the room.
LOG:         New Log event 'email_sent' on the sender's own feed (MAIL:
             block, mirrors the existing chat_message pattern) plus an inline
             MAIL: result under the Logs editor while sending (loading/error/
             success states, same UX family as /qi and /story).
GUARDRAILS:  <10 log entries -> "COHORT NOT YET FORMED" (mirrors /cohorts'
             own threshold); no match -> "NO COHORT MATCH: <NAME>"; recipient
             with no email on file -> DM still sends, emailDelivered:false.
