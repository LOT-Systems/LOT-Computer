02 // DESIGN NOTES
--------------------------------------------------------------------------------
RELIABILITY:  No server cron / push-notification infra exists in this repo
             (confirmed via repo-wide grep: no Notification API, no service-
             worker push). Reliability is therefore scoped to "while the tab
             is open, or reopened within 24h of the due time": the scheduler
             checks on mount, every 20s while the tab is visible, and again
             on every visibilitychange-to-visible. Entries overdue by more
             than 24h are treated as missed rather than fired, so reopening
             the widget after a long absence can't flood it with a stale
             backlog. "Already fired" is derived from the presence of a
             calendar_alert log carrying the source entry's id in its
             metadata — a durable, server-side fact, not a per-browser flag.
STYLE:       Kept strictly to the widget's existing minimalist idiom — plain
             text, acc/opacity color scale, uppercase tracking-widest labels
             (the same convention as the existing [SCHEDULE] prefix and the
             CAT:/CONF: bracket-labels already used across Logs.tsx). No
             Tag/Badge component, no color fills, no sound. The "military-
             grade" read comes from the terse [ALERT] bracket tag and
             monospace layout, not from decoration.
