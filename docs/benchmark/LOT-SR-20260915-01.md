WHAT CHANGED, PER REQUIREMENT:

1. Environment snapshot (weather/time/humidity/sky/location/astrology).
   `LogContext` already carried temperature/humidity/weatherDescription/
   city/country/timeZone/date/astro*. Added `sky`: a coarse read (clear/
   cloudy/overcast/rain/snow/storm/fog) derived from weatherDescription by
   `deriveSky()` in logs.ts, computed in `getLogContext()` alongside the
   rest. No photo, no audio — text/number fields only, as specified.
   Per-interaction (not just per-entry) snapshotting remains future work —
   marked honestly below, not claimed.

2. Passive Journal with follow-up on spike/pattern change. This was the
   real gap. `PUT /logs/:id` now calls new `maybeCreateEntryFollowUp()`
   after every autosave of 20+ characters: it re-reads the last 100 logs,
   builds a UserState via the (newly extracted, previously duplicated)
   `buildInterventionUserState()`, and asks the existing
   `generateCompassionateInterventions()` for a match. Only
   urgent_care / gentle_warning / pattern_awareness types qualify — a
   reaction to THIS entry, not general System-tab content. The existing
   (until now uncalled) `shouldShowIntervention()` cooldown gate is
   consulted before writing, keyed off the operator's last `qie_followup`
   log, so a struggle signal surfaces once per its severity window
   (critical 6h / high 1d / medium 2d), not on every autosave. When it
   fires, the follow-up is written as its own Log row (event:
   `qie_followup`) with the operator's own context attached, returned
   inline in the PUT response, and spliced into the Log tab immediately
   (`Logs.tsx` store update) right after the entry that triggered it —
   rendered as a `NOTICED:` block. The machine asks by writing back into
   the Journal itself, not a popup, not a required answer.

3. Compressed story, day/week/month/year. `/story` took a `range` param
   (`/story week`, `/story month`, `/story year`; bare `/story` still means
   today). Lookback window, log limit, sample size, word budget, and the
   AI prompt's framing now scale with range (day: 200 logs/24h/100-200w;
   week: 500/7d/150-250w; month: 1500/31d/200-350w; year: 4000/366d).
   `/system` documents the syntax. Along the way, fixed a real bug: the
   route filtered recent entries on `event === 'log_entry' || 'journal'`,
   but journal entries are created with `event: 'note'` (POST /logs) — so
   /story's "RECENT LOG ENTRIES" block was silently empty in production.
   Now includes `note`.

4. Data flow — Together AI as vendor processor. Verified, not changed:
   `/qi`, `/assembly`, `/prayer`, and `/story` all explicitly request
   `aiEngineManager.getEngine('together')`, not `'auto'`. The flow already
   reads LOT User data → these routes (Quantum Intent surfaces) → Together
   AI → a new Log row (LOT personalized data stored). No drift found.

5. Arcade tone. The new follow-up block (`NOTICED:`) and the extended
   `/system`/`/story` copy match the existing terse, bracketed, dense
   register used throughout Logs.tsx (`STORY:`, `QI:`, `ASM:` blocks) —
   no new UI language invented, no tone shift.

- Daily and yearly compression previously had no home at all (only weekly
