F4 QUANTUM-NAME DRIFT.  Three "Quantum*" widgets read three unrelated data
   sources: QuantumEngineWidgets/QuantumStateWidget read the real QIE
   nanostore (intentionEngine.ts); QuantumRandomWidget displays pure
   Math.random() and only *writes* to QIE via recordSignal(); QuantumSign-
   Widget uses stores.me + a date-seeded array, touching QIE at all. Naming
   implies shared backing that does not exist — cosmetic but S-2-relevant
   given the "quantum" brand language is user-facing copy.

   useMemory() -> GET /api/memory -> server-only #server/utils/memory
   (never imported client-side). NarrativeWidget -> useNarrative() ->
   GET /api/narrative, server-generated; client only blends display text.

F6 DATA PERSISTENCE — clean.  Sampled PlannerWidget/MemoryWidget/Recipe-

   Log, useMemory, useLogs, or store fetch). localStorage use is confined
   to cooldown/dedup UX (recentMemoryQuestions, lastRecipeShown), not
   primary data. No local-only-state widget found.

F7 DEPENDENCY DRIFT.  package.json pins nanostores ^0.9.0 but
   @nanostores/react ^0.4.1 peer-requires nanostores ^0.7.0 — `npm install`
   ERESOLVEs without --legacy-peer-deps; no .npmrc flag or CI install step
   papers over it. Every widget store (plannerWidget, rewardWidgets,
   recipeWidget, intentionEngine, chakraErgonomics, selfAssembly) sits on
   this stack. Not yet broken at runtime, but one clean-install away from
   blocking a fresh environment.

F8 BADGE ID COLLISIONS (adjacent to widget gamification surfaces).  esbuild

    exactly this purpose — but nothing in src/ ever inserts into it.

    to stderr/console; it never touches the table. Table is fully unwired.

F12 SPARSE INTERACTION LOGGING.  Only 3/37 widgets persist interactions
    server-side via useCreateLog: CalendarWidget, PlannerWidget, Recipe-
    Widget (-> POST /api/logs, the user's journal/mood log — not a generic
    event log). QuantumRandomWidget writes to intentionEngine's recordSignal,
    which is client-only, persisted to localStorage via a 250ms debounce
    (intentionEngine.ts:196,235) and never sent to the server. The other
    ~33 widgets (Memory, Intentions, MicroGame, Evolution, ChakraErgonomics,
    etc.) emit no cross-session-queryable interaction record at all.
    NET: there is currently no central, queryable log of widget usage
    across the platform — the infrastructure (audit_logs) exists but is
    dead weight; QIE "signals" are ephemeral and browser-local only.

F13 LIVE CONTEXT SYNC — present, narrow.  users_online/users_total/
    live_message arrive via sync.listen into nanostores (app.tsx:106-114,
    stores/state.ts:18-28); weather sets on load + interval (app.tsx:328).
    Consumed only by the header block + TimeWidget — not broadcast to or
    logged by any other widget.
