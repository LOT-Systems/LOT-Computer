05 // ROUTINES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
R1 TIME TRACKING     Added a Start (▶) / Stop (■) timer per calendar entry,
                     both in the "entries on selected date" list and the
                     upcoming-entries list (works with the calendar collapsed,
                     no extra clicks needed). Only one timer runs at a time;
                     other Start controls dim while active. Stopping writes a
                     new `calendar_time_log` Log row (date, entryType, text,
                     durationSeconds, startedAt, endedAt) via the existing
                     useCreateLog mutation — no new backend/table, consistent
                     with how calendar_entry already piggybacks on Log.
R2 RELIABLE TIMER    Active timer state persists to localStorage
                     (lot_calendar_active_timer) so a page reload / crash
                     mid-timer does not lose elapsed time — resumes ticking
                     from the original startedAt on remount. Elapsed display
                     updates every second via a guarded setInterval that only
                     runs while a timer is active (no idle polling cost).
R3 TRACKED-TIME BADGE Each entry now shows a small cumulative "Xm tracked"
                     badge (derived from summed calendar_time_log rows keyed
                     by date+type+text) next to its Start control, so time
                     already logged against a task/call is visible at a glance.
R4 EVENT NOTIFICATIONS "Military-grade" toast stack (bottom-right, stacked,
                     bracketed tags: [CAL::ENTRY] / [CAL::TIMER] /
                     [CAL::ALERT], monospace uppercase, auto-dismiss ~4.2s,
                     CSS-keyframe slide-in/fade-out). Fires on: entry created,
                     timer engaged, timer stopped (with duration logged), and
                     once per mount if any entries are due today. Modeled
                     directly on the existing EvolutionMilestoneToast.tsx
                     fixed-overlay pattern (only prior "toast" precedent in
                     the codebase) rather than inventing a new UI language.
R5 SIGNAL PARITY     Added recordCalendarTimeSignal(entryType, date,
                     durationSeconds) to intentionEngine.ts, mirroring the
                     existing recordCalendarSignal() for entry creation, so
                     the self-assembly/pattern engine sees time-tracking
                     activity on the same footing as note/task/call entries.
