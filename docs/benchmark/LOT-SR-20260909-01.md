05a // WHAT CHANGED
--------------------------------------------------------------------------------
POST /api/story now accepts an optional `period` ('day'|'week'|'month'|'year').
Unbounded /story is untouched (last 200 logs, no date filter — same as before).
A period request bounds the query to dayjs().tz(userTz).startOf(period), raises
the fetch limit to 2000 (a year of BIO/QIE signals is large), and computes:
  - PEAKS: max/min `energy` level (0-100, the only numeric per-log signal) in
    the window, each with its timestamp — the "high and low" the spec asked for
  - COMPRESSION WINDOW: active day count, journal word count, self-care act
    count, total signal count for the period
Both feed the AI prompt; the prompt explicitly instructs the model to name the
peak high/low as the story's emotional spine when a PEAKS block is present.
The generated Log now carries metadata.period, making period-story generation
itself a readable event for QIE/badges later — no badge minted for it yet.
Client: /story day|week|month|year parses the period, strips exactly the
matched token (not a generic word) so `/story <freeform text>` keeps its old
fallback behavior, and labels the appended story `📖 [WEEK] ...`. /system help
text updated to document the new syntax.
