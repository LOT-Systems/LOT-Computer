05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
R1 TIME-OF-DAY    CalendarEntry gained id + optional time (HH:mm, native
                  <input type="time">). Entries sort by date then time
                  (timed before untimed). Time renders inline in the
                  day view and the upcoming list. All-day entries (no
                  time set) behave exactly as before — additive only.
R2 REMINDER ENGINE  useEffect polls every 30s; a timed entry due (now >=
                  scheduled moment) fires once. Firing is deduped via a
                  capped (200) localStorage id list so a reload never
                  repeats an alert. Entries more than 30 min overdue are
                  marked fired silently (catch-up backlog guard) instead
                  of alerting all at once after a long-closed tab.
R3 MILITARY ALERT LOG  Firing writes a calendar_alert Log: text
                  "[ALERT] <type> DUE <time> — <text>", metadata
                  {date,time,text,entryType,sourceLogId}. Logs.tsx gained
                  an ALERT: handler (uppercase type + DUE, body text,
                  date/time line) beside the existing CAL: handler, which
                  now also shows time when present.
R4 NOTIFY + CHIME  In-widget ALERT: banner (Block, dismiss button,
                  30s auto-clear) using the existing label convention —
                  no new visual language. New playCalendarAlertChime()
                  (square-wave A5/E5 klaxon alternation) distinct from
                  the existing synth chimes. Optional browser
                  Notification, permission requested only on the direct
                  user action of saving a timed entry (never from the
                  background timer, which browsers would ignore/block).
R5 SIGNAL WIRING  recordCalendarAlertSignal() added beside the existing
                  recordCalendarSignal(); calendar_alert added to
                  selfAssembly SIGNAL_MAP -> 'calendar' (Temporal Planner
                  module) and to the server CALENDAR_EVENTS list used by
                  the temporal-alignment-peak background job.
