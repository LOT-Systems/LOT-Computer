WHAT CHANGED, PRECISELY:
- POST /api/story now takes an optional `period` (day|week|month|year,
  default day). Each period has its own log-window (1/7/31/366 days),
  signal sample cap (100/300/600/1200), and target narrative length
  (100-200w / 150-250w / 250-350w / 400-600w) — compression ratio increases
  with period length by design, not by accident.
- The client's `/story` trigger now parses a trailing period word
  (day|today|week|weekly|month|monthly|year|yearly) out of the log text,
  defaults to "day", and threads it through `useStoryGeneration`.
- `generated_story` added to the server's `displayableEvents` whitelist
  (src/server/routes/api.ts) — this event type has existed since
  SR-20260622-01 and was never in the whitelist; every /story output
  rendered once inline and then silently vanished from the Log on reload.
  Backend Whitelist Hygiene doctrine clause updated with this second
  occurrence.
- `generated_story` given its own `STORY [PERIOD]:` renderer in the Log's
  event-type switch (Logs.tsx), matching the `PRAY:` / `QI [RFI]:` styling
  of every other AI-backed command instead of falling through unlabeled.
- `/system` help screen now lists all four `/story` forms explicitly.
- New docs/technical/LOT-LOG-SYSTEM-WHITE-PAPER.md: the first consolidated
  reference for the Log — passive-UI philosophy, environment-context
  snapshot mechanism, full command surface, the /story compression
  pipeline (User Data -> QIE -> Together AI -> Personalized Data), how
  spike/pattern follow-up works without the Log itself prompting, and how
  the Arcade (badges, archetypes, self-assembly phases, RPG story-arcs)
  layer already rides the same Log event pipeline rather than living in a
  separate game screen.
