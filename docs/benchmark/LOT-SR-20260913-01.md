WHAT CHANGED:
- CalendarEntry gained a `time` (HH:mm) field. The add-entry form gained a
  <input type="time"> alongside the text field; time is optional.
- New `combineDateTime`/`formatCountdown` helpers merge date+time into one
  instant without a customParseFormat plugin (dayjs's own date-only regex
  parses locally, so no UTC-shift risk). Upcoming entries now render a live
  "T-minus Xh Ym" / "NOW" countdown, ticking every 20s while the tab is visible.
- Due-entry watcher: when a timed entry's moment arrives (within a 10-minute
  window), CalendarWidget fires one "SCHEDULE ALERT" toast (bottom-right,
  fixed, fade in/out, box-drawing bracket header ╞═╡, uppercase — no new font,
  no icons, no gradients, matching house voice) AND writes a
  `calendar_notification` Log entry so the alert is a durable record, not a
  disappearing toast. De-dupe key (date|time|text) persisted to localStorage
  so a reload doesn't re-fire an already-seen alert.
- Reliability fix: entry save previously cleared the input/closed the form
  unconditionally, even on a failed POST — a silent data-loss bug. Now the
  draft is only cleared on the mutation's onSuccess; onError keeps the draft
  and shows an inline "NOT SAVED — retry" line.
- Server: `calendar_notification` added to the GET /logs `displayableEvents`
  allowlist (src/server/routes/api.ts) — without this the new event would
  write successfully but never come back from the API, an invisible log.
  Found by reading the endpoint, not assumed.
