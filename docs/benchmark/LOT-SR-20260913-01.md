WHAT CHANGED:
- POST /api/story accepts optional `period: day|week|month|year`. When set,
  the log window narrows to that range (1/7/30/365 days back, limit scaled
  200/200/500/1500) instead of the unwindowed last-200. A PERIOD DIGEST block
  is computed server-side — total signals, dominant mood, journal/self-care/
  intention counts, and the single HIGH and LOW peak entry found in the window
  (first positive-mood and first hard-mood log hit, by the same mood-band
  classification the weekly Job 24 story already uses) — and injected into the
  Together AI prompt with an explicit instruction to name that specific moment
  rather than average it away. Bare /story (no period) is byte-for-byte the
  prior behavior; nothing existing regresses.
- /story day|week|month|year is parsed client-side in the same story-mode
  trigger (logTriggers.ts already matched "/story <word>" as one token —
  no detector change needed) and forwarded to the mutation.
- FIX: `generated_story` (the event POST /story writes per call) was missing
  from GET /api/logs' displayableEvents whitelist — a Backend Whitelist
  Hygiene violation (doctrine, SR-20260604-01): the write succeeded but the
  entry could never reappear in the Log feed after the in-session response
  faded. Added to the whitelist; added a dedicated STORY: render block
  (period + prose + HIGH/LOW peak rows) so it doesn't fall through to the
  generic LOG: block.
- /system help text lists the four period variants under /story.
