[2] PORTRAIT / PERSONAL PROFILE — GAP. No component is named "Portrait"; the
    live analog is PublicProfile.tsx (/u/:username, public-api.ts). It embeds
    ZERO of the interactive System-tab widget components — every field
    (correlated indexes, psychological profile, memory story) is a separate,
    hand-rolled read-only JSX block. Server math is shared (both call
    calculateCorrelatedIndexes() in memory.ts), but the two UIs and their two
    response shapes are independently maintained and can silently drift.

[3] QUANTUM INTENT ENGINE -> MEMORY — CONFIRMED SILENT-DROP, partially wired.
    QIE (client-side, intentionEngine.ts) IS wired to the server: recordSignal()
    calls syncToServer() every 10th signal (min 5 min apart), which
    bulk-writes Log rows with event:'quantum_intent_signal'
    (api.ts:3677). BUT: three independent formatLog() implementations exist
    for the Memory Engine's AI-prompt builder (memory.ts — LIVE, resolves via
    package.json's #server/utils/memory import map; memory/story-generator.ts
    — LIVE, used only by PublicProfile's story field; memory/question-
    generator.ts — DEAD, imported by nothing). Only the dead copy handles
    quantum_intent_signal. The two live formatters cover just answer/
    chat_message/note/settings_change/plan_set/emotional_checkin — so QIE
    signals, calendar_entry (CalendarWidget), self_care_skip/self_care_complete
    (SelfCareMoments), and medical_record/weekly_summary_response (server-
    tagged Memory answers) all reach the Log table but vanish before the AI
    ever sees them. Doctrine (LOT-DOCTRINE.md "Widget->Memory Compression
    Loop") already names this exact failure mode; this is its first concretely
    inventoried occurrence.

[4] STORY — FRAGMENTED. generateMemoryStory()/composeLocalStory() exist twice
    (memory.ts:873, used by the in-app Story feature via api.ts/admin-api.ts;
    memory/story-generator.ts:96, used only by PublicProfile via public-api.ts)
    and have already diverged: memory.ts's version does theme detection
    (morning/food/water/movement/sleep/focus) and time-span phrasing;
    story-generator.ts's is a plainer "portrait in N answers" fallback. The
    Portrait page's Story has quietly fallen behind the in-app one.

[5] LOG POSTING / COCKPIT-RULE — ONE CONFIRMED VIOLATION. Most widget->Log
    paths are compliant (spot-checked calendar_entry, plan_set). One live path
    is not: POST /emotional-checkin (api.ts:1654-1698) generates full prose
    ("You've felt calm for 3 days in a row", "Your mornings tend to be
    energizing") into metadata.insights, which Logs.tsx renders verbatim
    inside the BIO block body — narration where doctrine reserves the body for
    instrument readings only.
