NEW DOCTRINE CLAUSE — Migration-Model Parity:
  A Sequelize model, its routes, and its client component can all exist,
  import cleanly, and type-check with zero errors while the table backing
  the model was never created by any migration. `direct_messages` was such
  a case: DirectMessage model (2024-era), POST/GET /direct-messages routes,
  and DirectMessageThread.tsx all shipped and typechecked fine on master —
  but `grep -rl direct_message migrations/` returned nothing, and no
  `sequelize.sync()` exists anywhere to paper over it at runtime. The
  feature was dead on arrival: any call would 42P01 (relation does not
  exist) against a live database. TypeScript has no way to see this failure
  mode — it only sees the model class, never the schema. Before building
  new routes on an existing model, grep migrations/ for its table name;
  absence is not "already handled elsewhere," it is a missing migration.
  (SR-20260913-01: added migrations/20260913000000_add-direct-messages.cjs
  — retroactively fixes the pre-existing DirectMessage/DM-thread feature
  as a side effect of building LOT Mail on top of it.)
