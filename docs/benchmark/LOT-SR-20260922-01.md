  fetch-once-per-mount, acceptable for a slow-changing value.

LOG-POSTING SPLIT (answers the "military-communications Log" question):
  Two distinct, both-legitimate pipelines exist, not a bug:
    1. useCreateLog() -> POST /api/logs — used by Planner, Calendar, Memory.
    2. recordSignal() -> local intentionEngine buffer -> batched
       POST /api/quantum-intent/sync every 10 signals or 5-minute cooldown
       (intentionEngine.ts:79-80,247-251) — used by QuantumState, Intentions,
       SystemPulse-adjacent signals, GoalJourney cross-widget cascades.
  Interactive widgets ARE synchronized and eventually logged server-side;
  the "Data log of all widget usage" ask is satisfied by pipeline 2's server
  persistence, batched rather than per-click. This is intentional lag-control
  (documented inline as an interaction-responsiveness tradeoff), not neglect.

LOADING SPEED (proxy: prod client bundle sizes, dist/client/js):
  app.js 716K, about.js 432K, largest vendor chunk 236K. No single widget
  dominates; About.tsx's 432K is pure static prose and the single largest
