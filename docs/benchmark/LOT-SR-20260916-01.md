05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
LOG COMMAND     "/email to <name>" is a new entry in the existing slash-
                command registry (logTriggers.ts), detected the same way as
                /prayer, /story, /qi. Flow matches those exactly: type the
                message body, then append "/email to <name>" — the command
                fires once (fresh-trigger semantics), strips itself out of
                the log text, and sends whatever body text remains.
DELIVERY        POST /api/lot-mail resolves <name> against real users
                (case-insensitive firstName match, Op.iLike); creates a
                lot_mail row regardless of match; emits sync.emit('lot_mail',
                ...) filtered server-side to sender+recipient only (private,
                unlike public chat broadcast); writes a Log 'email_sent'
                entry for pattern-analysis parity with chat_message.
SYNC SURFACE    Sync.tsx now merges GET /api/lot-mail + the 'lot_mail' SSE
                event into the same feed as chat, rendered as "✉ to <name>:
                <body>" envelope rows, sorted by time with chat, like-toggle
                disabled on mail rows.
COMMUNITY LINK  CohortConnectWidget's per-match action is now "Email" (was
                "Send message", previously a no-op navigate to Sync). It sets
                a small pendingEmailRecipient hint atom and jumps to Log,
                where a dismissible one-line banner reminds the user to send
                with "/email to <name>".
GATE            Both LOT Email routes require the same tags as Chat
                (Usership/Onyx/Legacy/R&D/Admin, non-suspended) — one
                participation gate for both surfaces, matching existing
                convention (chat likes were unified with posting the same
                way in SR-20260719-01).
