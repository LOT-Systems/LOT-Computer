DESIGN (the simplest thing that works)
--------------------------------------------------------------------------------
DATA     One table `emails`: senderId, receiverId, subject, body, readAt.
         No folders, threads, attachments, cc/bcc. Internal LOT users only —
         no external SMTP, so no deliverability or spam surface.
API      GET  /api/emails             inbox (50) + unread count
         POST /api/emails             send {receiverId, subject?, body}
         POST /api/emails/read        mark own mail read
         GET  /api/emails/recipients  name search (first/last, iLike, top 5)
         Limits: subject 200, body 10000. Self-mail rejected. Receiver verified.
LOG      Typing "/email to Hitomi." opens an EMAIL: panel in Log. Name is parsed
         from the text ("to" optional, trailing punctuation stripped), resolved
         against users; one match auto-selects, several are listed to pick.
         Then subject + body, Send. Listed in /system help.
SYNC     MAIL (n unread) block above the chat: list, ● unread dot, click to
         open + mark read, reply, compose. Live: server emits `email` over SSE,
         forwarded ONLY to the receiver's stream; client invalidates inbox.
         Mail shows even for users without chat access (chat stays gated).
COHORT   Cohort widget (powered by /api/cohorts matches) gains an "Email"
         button -> sets emailDraftTo, jumps to Sync with composer prefilled.
         Cohort Dating therefore flows: match -> Email -> inbox of the other
         person in Sync.
AUDIT    Each send logs an `email_sent` event to Logs (receiverId only, no body),
         parallel to `direct_message_sent`.

HONEST BOUNDARIES
--------------------------------------------------------------------------------
* Migration NOT executed: no database in this environment. Run
  `yarn migrations:up` on deploy (production:run already does).
* No browser/E2E test of the Log -> Sync flow was run; verification is
  typecheck + production build + parser sanity check
  ("/email to Hitomi." -> "Hitomi"; "/email" -> "").
* "/email" fires on typing as any Log trigger does (existing mechanism);
  the panel opens at "/email" and follows the name as you type it.
* "Hitomi" resolves only if a LOT user with that first/last name exists.
  Recipient search is across all users; it is NOT yet restricted to
  cohort/community members and does not rank them first (code comment in
  the route says so aloud—tighten if privacy requires).
* "Cohort Dating through LOT Community": integrated at the cohort widget.
  The /community page itself was not modified. Mutual-consent gating
  (only matched pairs may email) is NOT implemented — recommended next.
* No rate limiting on POST /api/emails beyond existing app-level behavior.
  Recommended before wide release.
* Gmail connector was available but deliberately unused: v1 is internal mail.
* Existing gap noted, not fixed: SSE `direct_message` is emitted server-side
  but not forwarded in the /sync switch.
