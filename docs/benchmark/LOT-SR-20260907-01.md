05 // WHAT WAS ACTUALLY FOUND — SHIP ATTEMPT AND WHY IT STOPPED
--------------------------------------------------------------------------------
The manifest's "QI-46 Engine" entry pointed to branch
claude/cool-tesla-f8j0mr, hash 36ef4dde, marked BEST. Fetched it. The
branch as a whole is ~3 months stale against master (diff shows 147k+
deleted lines — badge codexes, wikis, session reports master gained since
— none of that is real, it is just drift). But only two commits on that
branch are actually exclusive to it: f7ab28ca and 36ef4dde, both
2026-06-11. Isolated those and cherry-picked them onto a throwaway staging
branch built from origin/master. Both applied with a clean auto-merge, zero
conflicts. Two doc files had landed at repo root in the original commit
(should have been under docs/assembly/) — moved them there in staging.

Read the resulting code in full before going further, per this protocol's
own judgment-boundary rule (broad-scope artifact -> HOLD and surface,
don't guess). What it does, concretely:

- New files: qi46-vocabulary.ts (mirrors a subscriber's own journal
  phrasing back at them), qi46-soul.ts (keyword-pattern classifier over a
  subscriber's check-ins/notes -> a 5-axis "humanoid calibration":
  grace/poetry/love/presence/ease, "male" fixed as tone carrier not a
  variable), qi46-engine.ts (assembles both into a system prompt, calls
  `anthropic.messages.create({ model: 'claude-sonnet-4-6', ... })` for
  real, live).
- Wired into src/server/routes/api.ts on the real emotional-check-in
  endpoint, gated to subscribers tagged 'usership' — i.e. this runs for
  real paying subscribers on real submitted text, not a demo.
- Has a real output filter, cosmoScreen(), which is honestly a solid
  build: it rejects generic-AI-voice phrasing, over-length responses,
  false-certainty claims, and self-harm-adjacent words IN THE MODEL'S
  OUTPUT, falling back to a static safe line if held.

The problem: cosmoScreen()'s "clinical escalation" flag list also rejects
the model's own output for containing "professional help," "see a
doctor," "therapy required," "diagnosis," etc. — on brand-voice grounds
(LOT® doesn't sound clinical). That is reasonable for ordinary tired/
anxious/overwhelmed check-ins. It is not reasonable as the *only* gate: if
a subscriber writes something indicating real crisis in their check-in
note, and the model appropriately tries to point them toward a person or
a hotline, this exact filter swaps that out for a poetic one-liner
instead, because the appropriate response is exactly the kind of language
this filter treats as off-voice. I checked the rest of the codebase for
any independent crisis/self-harm detection on the *subscriber's own input*
(grep across src/server and src/client for suicide/self-harm/crisis/
hotline/988) — the only hits are this same file's output-side filter and
one line of ToS boilerplate in About.tsx ("if you are experiencing a
mental health crisis, contact a qualified professional"). There is no
active, input-side safety net upstream of this feature. That is a real gap
for a feature that ingests real subscribers' free-text emotional state,
not a hypothetical edge case.

DECISION: did not merge to master, did not push the staging branch, did
not touch the live cool-tesla-f8j0mr branch. Reverted local staging
entirely (branch deleted, working tree confirmed clean against origin).
Manifest entry changed BEST -> HOLD with a pointer to this report; the
2026-06-27 manifest note claiming this branch was already absorbed into
master was checked and is false for this feature specifically (flagged in
the manifest; the other five branches in that note were not re-checked).
Corporate engine spec (LOT_QI46_ENGINE.md) got a dated checkpoint section
recording the same finding for whoever reads that file next.

This is exactly the judgment-boundary case this protocol calls out by
name: broad scope, real subscribers, a genuine safety question. Recording
it and surfacing it is the honest outcome here, not fabricating a ship
that shouldn't happen unreviewed.
