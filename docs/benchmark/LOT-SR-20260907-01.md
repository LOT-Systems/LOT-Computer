WHAT CHANGED, functionally:
- POST /api/story now accepts `period?: 'day'|'week'|'month'|'year'`. When
  present, the log query window narrows to that range (Op.gte on createdAt),
  the sample size and target word count scale with it (day: 60-100w / 5
  samples; week: 100-200w / 10; month: 200-300w / 20; year: 300-450w / 30),
  and the system prompt tells the model explicitly it is compressing a named
  window, not just "recent" — matching S-2's own framing: "creates a
  compressed story of your day/week/month/year and sends it back."
- The client /story trigger (Logs.tsx) parses `/story day|week|month|year`
  out of the log text, strips it before sending logText, and forwards
  `period` to the mutation. Plain `/story` (no argument) is unchanged —
  same "recent journey" behavior shipped in SR-20260622-01.
- generated_story log rows now carry `metadata.period` ('recent' when no
  window given) — this is the hook a future badge/pattern job would key on
  to reward periodic reflection (see 06, WORDS/GAMIFICATION note below).
- /system help text and the LogTrigger type comment updated to document the
  four period variants.
