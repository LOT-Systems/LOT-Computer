NOTES:       Design notes for the next session touching this feature:
             - Recipient resolution is by-name (case-insensitive first/last)
               across the whole User table, not scoped to a cohort — "Cohort
               Dating" itself does not exist as a feature anywhere in the
               codebase (confirmed via grep); the honest integration point
               built here is the ✉ Mail button on ChatCatalystWidget's cohort
               matches, which pre-addresses the same /email command. Calling
               this "Cohort Dating" in the S-2 brief is PROVISIONAL framing —
               what exists is cohort-to-mail reach through LOT Community's
               existing behavioral-cohort matching, not a dating feature.
             - `/email to <Name>` fires once per detectNewTriggers boundary
               (same single-fire limitation as the existing /qi command) —
               solved the same way the June branch solved it: the trigger
               opens an editable inline compose box (name pre-filled, body
               editable, explicit Send), so the single fire only needs to
               capture the name, not the whole message.
             - Two unrelated pre-existing gaps found, NOT fixed (out of scope
               for "simplest"): `direct_message` SSE event has no case in the
               server switch (never delivered to any client), and SyncEvents
               type keys (chatMessage) don't match the runtime event strings
               (chat_message) used everywhere. `lot_mail` was added consistent
               with the runtime convention (snake_case), not the mismatched type.
             - This is not the first attempt at this exact feature: the
               manifest's "determined-turing" branch cluster (89 remote
               branches, this session's own prefix) already carried an 11/11
               BEST iteration in June. That branch is now too stale to merge
               (147K-line divergence) — recommend the manifest's ship queue
               drop the June hash and point at this session's commit instead.
