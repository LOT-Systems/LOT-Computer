            and mounted in System.tsx (1071 lines, hardcoded JSX composition,

PORTRAIT    About.tsx (src/client/entries/about.tsx, 4889 lines) is the
            Portrait/profile wiki page. It DESCRIBES widgets in prose
            (`widget-ecosystem` section, L2631) but mounts no live widget
            components — it is documentation, not a rendering surface. Correct
            as designed, but means Portrait cannot drift from live widget
            state since it never reads it; verify manually on doc edits.

QIE/MEMORY  QIE is client-side only: intentionEngine.ts recordSignal() (L199)
            writes to a localStorage-persisted atom (7-day retention,
            WIDGET_DEPENDENCY_MAP / LOG_DEPENDENCY_SOURCES at L4074-4076).
            Memory Engine (server, memory.ts buildPrompt() L241) is fed
            separately by server Log entries via formatLog() (L784) plus
            plannerContext (L307-316). THESE ARE TWO SEPARATE PIPES: widgets
            calling recordSignal() only (Intentions, ContextualPrompts,
            ChatCatalyst, Interventions, MicroGame, Chakra, GoalJourney,
            PatternInsights, and more) feed QIE/derived-widget display but
            NEVER reach the AI's Memory prompt or the Log — only PlannerWidget,
            CalendarWidget, RecipeWidget, SelfCareMoments call useCreateLog()
            and reach both. No server->widget push channel exists (no SSE/WS);
            all QIE/Memory feedback to widgets is poll/refetch. Confirms and
            extends existing doctrine "Async Signal Recording" — signal and
            log are not the same channel and must not be assumed equivalent.

LOG GAP     `weather_update`, `user_login`, `user_logout`, `theme_change` are
            whitelisted in the /logs displayableEvents filter (api.ts ~L1098)
            WITH dedicated render branches in Logs.tsx (L1824-1848), but no
            code path anywhere calls Log-create for them (grep clean). TimeWidget
            renders weather/time live but never posts a weather_update entry.
            This is the exact gap S-2 flagged — "context can be synchronized
            (weather, time, users online) and posted to the Log" — currently
            it is displayed but not logged. This is the mirror image of the
            existing "Backend Whitelist Hygiene" doctrine clause (POST without
            GET-whitelist = silently unreadable); here it's GET-whitelist
            without any POST = permanently empty, dead whitelist entries.
            Judgment boundary: implementing this is a product decision (log
            weather on every poll vs. on-change only; login/logout log volume
            at scale) — held for S-2 rather than guessed at.

PERF/LAG    Prior fixes (SR-20260719-01) verified STILL IN PLACE, no
            regression: 7 stats endpoints in queries.ts (L601-693) at
