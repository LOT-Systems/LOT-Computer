## DISCOVERY — PRIOR ART AND LATENT GAPS

```
A prior feature branch (claude/determined-turing-f6bw7r, "LOT Mail", 11
iterations, never merged) had already designed this exact feature. It was
stale relative to current master, but its shape — dedicated LotMail model
(subject/body/read), recipient lookup by name across "LOT Community", a
Sync "Mail" tab, dedicated `lot_mail` SSE event scoped to the recipient —
was sound and is what this session re-implemented fresh against current
master, rather than re-merging the stale diff.

Two pre-existing gaps were found in the DirectMessage (1:1 chat) feature
while researching Sync — noted here, NOT fixed (out of scope for this
task, flagged for a future session):
  1. `direct_messages` table has a Sequelize model + API routes + client UI,
     but NO migration ever created the table — it may not exist in production.
  2. The SSE relay's `sync.listen('*', ...)` switch in api.ts has no
     `case 'direct_message':`, so `sync.emit('direct_message', ...)` is
     never forwarded to any client — DM live-updates are dead code today.
LOT Mail does not depend on either gap: it uses its own new `lot_mails`
table (migrated in this session) and its own `case 'lot_mail':` SSE case,
scoped to `toUserId === req.user.id`.
```

## BUILD — LOT MAIL v1

```
Command    : /email to [name]   (also /mail to [name]; ✉️ ✉ 📧 also arm it)
Flow       : Log entry → detects trigger → inline "✉ MAIL:" compose box
             opens (To: [name], body textarea, Send/Cancel) → POST /api/mail
             → resolved recipient gets it live in Sync's "Mail" tab via SSE.
Recipient  : Resolved by first name (or "first last"), case-insensitive,
             across ALL registered users — the "LOT Community" pool — not
             limited to existing chat/cohort connections.
```

### New — data layer

```
migrations/20260910120000_add-lot-mail.cjs

```

### New/changed — server API (src/server/routes/api.ts)

```
POST /api/mail            body {toName, body, subject?}
                           → 400 missing fields / self-send
                           → 404 {error, hint: 'No user named "X" in LOT
                             Community'} if no match
                           → creates LotMail, emits SSE 'lot_mail' (scoped),
                             logs a `lot_mail_sent` Log row (fire-and-forget,
                             matches the direct_message_sent precedent)
GET  /api/mail/inbox       last 50 mails to req.user, joined sender names
GET  /api/mail/unread-count  {count} — for the Sync tab badge
PUT  /api/mail/:id/read    marks one mail read (scoped to toUserId)

SSE relay switch (existing `sync.listen('*', ...)` in GET /sync):
  + case 'lot_mail': forwards only when data.toUserId === req.user.id
    (same pattern as the existing 'settings_updated' case — every other
    connected client's handler silently drops it)

Shared additions: LotMail / LotMailRecord / LotMailSyncPayload types
(src/shared/types/index.ts), MAX_LOT_MAIL_LENGTH = 2000
(src/shared/constants/index.ts).
```
