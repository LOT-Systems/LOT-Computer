## 3. Blocking decisions (physics, not preference)

**D1 — 5 mm is extremely tight.** Stack budget (mm): two steel shells 2×0.5 = 1.0 · PCB 0.8 · battery 3.0 · = 4.8 before screen, camera, coil, or components. Screen + coil + camera do not fit in 0.2 mm.
- Recommend **Gen 0 = 40×40×9 mm** (steel shells 0.8 mm), prove everything, then thin to 5–6 mm in Gen 1 with a custom flex-PCB + thin camera.
- Alternative to hold 5 mm now: drop the camera or the battery (tethered). Not recommended.

**D2 — Stainless steel blocks radio and Qi charging.** A closed metal body is a Faraday cage: Wi-Fi/BLE and wireless charging will fail.
- Wi-Fi/BLE: use the **split line between the two shells as a plastic-filled slot** with a ceramic chip antenna beside it, or a small non-metal antenna window.
- Qi: needs a non-metal window. Recommend the **screen side** has a glass/ceramic panel (it already must) and the Rx coil sits behind a ferrite sheet under a **non-conductive inset on the rim/back**, OR charge through a dedicated 10 mm plastic/ceramic disc inset in the polished back (hurts the "pure polished" look). Thin steel (<0.2 mm) transmits poorly and heats; do not rely on it.
- Fallback: magnetic pogo-pin dock (reliable, no RF issue) as Gen 0 charger alongside Qi.

**D3 — Power class.** Wi-Fi + camera + screen on ~100 mAh = hours, not days. Define behaviour: **screen/Wi-Fi sleep, wake on button / scheduled poll / BLE push**. Realistic Gen 0 target: 2–3 days with 5-min poll; camera on demand only.

## 4. Hardware design (Gen 0)

**Architecture:** ESP32-S3 (Wi-Fi + BLE + camera + USB) as the single brain; sensors on I²C; PMIC + wireless Rx + fuel gauge on the power side.

**Body:** 316L stainless, CNC, 2 parts. Back = flat polished mirror (#8 finish, "flat silver"). Front = bezel + window for screen, camera aperture, one side-mounted button. Joined by M1.0 screws or laser weld; plastic gasket forms the RF slot. Marking: laser-engraved LOT mark + serial.

## 5. Firmware & software

- **Firmware:** ESP-IDF 5.x (C), FreeRTOS tasks: `net` (Wi-Fi + TLS client), `ui` (LVGL on ST7789), `sensors`, `power`, `button`.
- **Flow:** boot → provision (token) → connect → **poll `GET /api/device/inbox` every N min and/or hold WebSocket when charging** → render message + beep → button press → `POST /api/device/event`.
- **Provisioning tool:** web page using Web Serial / BLE to set Wi-Fi + `operator_token`, flash firmware (esptool-js), view device log. Lives in the LOT site (`/device`) or a standalone `lot-flash` CLI.
- **OTA:** signed images (ESP-IDF secure boot v2), A/B partitions. Required before shipping 100 units.
- **Camera:** on-demand snapshot → compress JPEG → `POST /api/device/snapshot` (rate-limited). Consider privacy: indicator on screen when camera is on.
- **Security:** per-device key, TLS pinning, token revocation, no secrets in firmware image. Matches repo `SECURITY.md` posture.

## 6. LOT API connector (proposal — not implemented)

All new server code is out of scope this session. Proposed contract, aligned with Node 19 M2M format 3:

```
POST /api/device/pair           -> { device_id, device_token }   (user confirms on site)
GET  /api/device/inbox?since=…  -> [{ id, text, level, ts }]     ("Coffee time!")
POST /api/device/event          -> { device_id, type:"copy", ts, battery }  -> creates Log entry
POST /api/device/telemetry      -> { temp, hum, pres, voc, lux, battery, rssi, ts }
POST /api/device/snapshot       -> multipart JPEG
Auth: Bearer <device_token>, per-device, revocable; rate-limited (existing fastify rateLimit).
```

- **"Copy" button** → `type:"copy"` creates a Log entry visible in the **Log tab** ("Copied from device LOT-xxxx at HH:MM"). Needs a Log source tag for devices.
- **Notifications:** AI engine already runs on the site; add a scheduled job (`scheduled-jobs.ts`) that generates short contextual nudges and writes to a `DeviceMessage` table → inbox. Keep to ≤ 60 chars for the screen.
- Day-1 shortcut: device can poll existing `GET /api/live-message` while the new endpoints are built.
