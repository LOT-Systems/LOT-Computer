## 1. Product definition

A 40 × 40 × 5 mm flat stainless-steel "pager" computer that receives autonomous notifications from lot-systems.com (e.g. "Coffee time!"), shows them on a small screen, captures photos, senses weather, and reports a "Copy" button press back to the site's **Log** tab.

| Spec | Target |
|---|---|
| Size | 40 × 40 × 5 mm (hard envelope, includes body walls) |
| Body | 316L stainless, **2 parts** (front bezel + back plate), laser-welded or screw/snap-sealed |
| Back | Mirror-polished stainless (flat silver) |
| Front | Screen + camera + button |
| Connectivity | Wi-Fi 2.4 GHz (BLE for provisioning) |
| Charging | Wireless (Qi-class) — see risk R1 |
| Sensors | Temp / humidity / pressure / gas (BME688-class) |
| Cloud | LOT API connector, outbound HTTPS/WebSocket only |
| Volume | 100-unit first run |

## 2. Architecture

```
 lot-systems.com (AI notification engine)
        │  push: WebSocket / MQTT-over-TLS (poll fallback every 30–60 s)
        ▼
  LOT API connector  ──►  /api/device/* (NEW)  ──►  Log tab (event: COPY, weather, photo)
        ▲
  Device: ESP32-S3 + display + OV camera + BME688 + button + Qi RX + LiPo
```

Device-side flow: wake → fetch/receive notification → render on screen + haptic/buzzer cue → button "Copy" → POST `{device_id, event:"copy", notif_id, ts, weather}` → Log tab entry. Sensors sampled on schedule and batched (low-power).

## 4. Hard engineering risks (ranked)

- **R1 — Wireless charging vs. stainless.** Metal blocks Qi fields; a fully stainless body with a polished stainless back will not charge. Options: (a) non-metal charging window (PEEK/ceramic/sapphire disc ≥ coil diameter) set into the back — breaks the pure-polished look; (b) make the 2-part split a non-metal mid-ring and put coil behind it — weak coupling; (c) use thin front glass side as charging face; (d) **recommended for EVT: pogo/magnetic contacts**, and prototype (a) in parallel. Decision needed from Inventor.
- **R2 — 5 mm stack.** Camera (~4–5 mm) + screen + battery + PCB + two 0.5 mm walls won't fit in 5 mm in a single layer at 40×40. Likely options: camera in a lens-nub (relaxes flat spec locally), 0.96" OLED + smaller camera (GC0308/OV7670 FPC), or relax to 6–7 mm. Needs mechanical CAD before PCB layout.
- **R3 — Wi-Fi inside a steel can.** Needs antenna on a non-metal window or slot; expect heavy detuning. Budget RF tuning.
- **R4 — Battery life.** Always-on Wi-Fi in 300 mAh is days at best; use poll/DTIM or BLE-bridged wake. Define the latency target.
- **R5 — Compliance.** FCC Part 15 (intentional radiator), battery UN38.3, CE if exported. Use pre-certified ESP32 module to limit cost.
- **R6 — Camera privacy.** Capture only on explicit button/command, hardware LED, no silent upload.

## 5. Software & firmware

**Firmware (ESP-IDF, C/C++):** provisioning (BLE → Wi-Fi), TLS client w/ device cert, notification receive/render, button ISR, sensor loop (BSEC), OTA (signed), power manager, camera capture (on demand).
**Host software:** `lot-flash` CLI (esptool wrapper, serial provisioning of `device_id` + key, factory test), plus a test-jig script.
**Server (this repo) — NEW, not yet built:**
- `POST /api/device/register`, `GET /api/device/notifications` (or WS), `POST /api/device/events` (COPY, sensor, photo ref), per-device token auth.
- Log tab: new event type `device.copy` rendered with device ID, timestamp, notification text.
- Notification generator: AI-authored short strings (≤ 40 chars for screen), rate-limited.
Existing `/api/os/*` can feed content (status/insights → pager text).
