# 03 — Firmware and LOT API connector

## Firmware (ESP-IDF or Arduino-ESP32, PlatformIO)
- Boot → load device token from NVS → Wi-Fi → `GET /api/device/notifications?since=<id>` every N min (light sleep between; deep sleep when battery < 15%).
- Render: title line + body (≤ 3 lines at 240x240), LED-free; vibration motor optional later.
- Button: short press = "Copy" → `POST /api/device/events {type:"device_copy", notificationId}`; long press = capture photo (v0.2).
- Sensors: every 10 min read BME688 → buffer → batched `POST /api/device/telemetry`.
- OTA: signed images, HTTPS, rollback on failed boot.
- Repo layout: `firmware/` (src, platformio.ini, CHANGELOG.md), one firmware doc per release (item 9).

## Server-side LOT API connector (new, not yet implemented)
Existing: `fastify` routes in `src/server/routes/api.ts`; `/logs` filters by an allow-list of event names (`displayableEvents`, ~line 1083), so the new event type must be added there or it will not appear in the Log tab.
| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /api/device/pair` | user session → one-time code | Binds device to user, returns device token |
| `GET /api/device/notifications` | device token | Pending notifications |
| `POST /api/device/events` | device token | `device_copy`, `device_ack`; writes a Log event (add `'device_copy'` to `displayableEvents`) |
| `POST /api/device/telemetry` | device token | Weather/IMU batches |
| `POST /api/device/photo` | device token | JPEG upload (size-capped) |
Needs: a `Device` model (id, userId, tokenHash, lastSeen, fw), a notification queue, rate limits, token revocation. Notifications text can be generated by the existing AI services (e.g. the Anthropic client already used in the server).

## Software to connect with firmware
- Site page "Devices": pair code, battery/last-seen, notification test button.
- Web flasher (Web Serial + esptool-js) hosted on the site.

## Security
Device tokens hashed at rest, TLS only, per-device revocation, signed OTA, no secrets in firmware images.
