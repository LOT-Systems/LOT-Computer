## 2. SYSTEM ARCHITECTURE

```
 lot-systems.com (Fastify + Prisma)            LOT BEACON P1
 ┌──────────────────────────────┐   HTTPS    ┌─────────────────────────┐
 │ QIE / AI engines → notify()  │───────────▶│ ESP32-S3 (Wi-Fi/BLE)    │
 │ /api/device/* (NEW)          │◀───────────│ screen · buzzer · button│
 │ Log table → Log tab          │  events    │ camera · BME688 · light │
 └──────────────────────────────┘            │ Qi Rx → charger → LiPo  │
                                             └─────────────────────────┘
```

- **Transport:** device long-polls (or SSE, the server already has SSE in `api.ts`) — deep-sleeps between polls; wake on button/motion. Target avg < 0.5 mA.
- **Auth:** one-time pairing code shown on the site (Settings) → device receives long-lived per-device token. Token stored in ESP32 flash encryption + secure boot v2.
- **Privacy:** camera is **off by default**, captures only on explicit user action, hardware LED/shutter-cover is a v2 item. Not uploaded without an explicit user pairing flag.
- **AI:** notifications are generated server-side by the existing AI engines; the device is a dumb terminal (no on-device LLM). "AI-grade sensors" = BME688 + Bosch BSEC gas-classification, optionally motion-based activity detection.

## 3. MECHANICAL — THE HARD PART

### 3.1 Z-stack for 5 mm (honest budget)

| Layer | mm |
|---|---|
| Front steel shell (top wall) | 0.4 |
| Display module (bare IPS) | 1.5 |
| Main PCB (0.8 mm, both sides, tall parts ≤ 0.6) | 1.4 |
| LiPo 100–150 mAh (pouch) | 2.0–2.5 |
| Qi coil + ferrite | 0.5 |
| Back plate | 0.4 |
| **Sum** | **6.2–6.7** |

**Conclusion:** 5 mm is not reachable with a stacked build and a camera that has a lens barrel (bare OV2640-class ≥ 4 mm tall). Options:
- **v1 (recommended):** 8 mm, same 40×40 footprint. Ships the full feature set.
- **v2:** 5.0 mm via flex-rigid PCB, side-by-side battery/coil (not stacked), sub-3 mm camera module. Needs custom flex via PCBWay (flex/rigid-flex offered).
- **Alt:** 5 mm body with a ~2 mm camera bump.

### 3.2 Steel
- 316L, 0.4 mm sheet. Front shell: CNC or deep-draw + CNC; back plate: stamped + polished. Weld seam or 4× M1.0 micro-screws + silicone gasket.
- Finish: mirror polish (back), brushed or bead-blast (front, hides fingerprints).
- 100 units: CNC both parts (~best for 100); stamping tooling only pays off at 1,000+. PCBWay lists CNC and sheet-metal services; also compare Xometry/JLC3DP/local shops.

### 3.3 RF & wireless charging (flagged)
- **Qi through steel does not work** (eddy currents). The coil must face a non-metal area: a ceramic/PEEK/glass **charge window** in the back plate (round, ~28 mm) inlaid flush — or move charging to the front glass side (coil under display; hurts z-height). Decision D2.
- **Wi-Fi/BLE** through a closed steel can is blocked: place the antenna beneath a plastic/ceramic gap (ceramic window doubles as antenna window) or use the shell split as a slot with a plastic insert. Plan an RF test round in P0.

## 6. LOT API CONNECTOR (proposed; not in repo today)

Repo check: no device routes exist; `Log` writes go through `fastify.models.Log.create({event, ...})` in `src/server/routes/api.ts`, and the `/logs` endpoint filters by an allow-list (`displayableEvents`).

| Endpoint | Purpose |
|---|---|
| `POST /api/device/pair` | Exchange site-issued 6-digit code → device token |
| `GET  /api/device/notifications?since=` | Long-poll; returns `{id, text(≤64ch), sound, ts}` |
| `POST /api/device/events` | Device events: `device_copy`, `device_battery`, `device_weather` |
| `POST /api/device/ack` | Notification shown/dismissed |

Required server changes: `Device` Prisma model (id, userId, tokenHash, lastSeen, fw), device-token auth hook, add `device_copy` (+`device_weather`) to `displayableEvents` so it renders in the **Log tab**, and a `notify()` helper that AI jobs (e.g. "Coffee time!") can call. "Copy" semantics need a decision (D4): copy *what*? Proposed: the currently displayed notification text is logged as saved/acknowledged.

## 7. MANUFACTURING FLOW & PCBWAY

1. KiCad → Gerber + BOM + CPL → PCBWay quote (PCB + turnkey assembly; BOM by MPN). PCBWay quotes assembly manually, ~1–2 business days; panelize (board < 50 mm, > 20 pcs).
2. Shell parts: PCBWay CNC (or alt vendor) → polish → ultrasonic clean.
3. Final assembly + firmware flash + factory test (jig), laser-engraved serial.
4. Compliance for sale: FCC Part 15 (intentional radiator; pre-certified module helps), CE-RED, battery UN38.3 shipping, RoHS. Wireless-charging Rx adds testing.

## 11. RISKS & DECISIONS FOR S-2

| Risk | Severity | Mitigation |
|---|---|---|
| 5 mm unreachable in v1 | High | D1: accept 8 mm v1 / 5 mm v2 |
| Steel kills Qi + RF | High | D2: ceramic/PEEK window; test in P0 |
| Camera privacy / regulation | Med | Off by default, explicit capture, no auto-upload |
| Battery safety (thin LiPo in sealed steel) | Med | Protected cell, thermal cutoff, UN38.3 |
| Regulatory cost/time | Med | Pre-certified module, budget reserve |
| Brand: "COSMO®" naming vs gating | Low | D3 |

**Decisions needed:** D1 height (8 mm v1 vs hold 5 mm); D2 charge-window material/side; D3 product name/branding (BEACON vs COSMO®); D4 "Copy" semantics; D5 camera in v1 (capture-only vs defer to v2).
