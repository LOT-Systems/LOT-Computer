# LOT PAGER — Device API Spec v0.1 (DRAFT)

Status: proposal. Nothing here is implemented in `src/server` yet.
Existing hooks (verified in repo): `GET /api/logs` in `src/server/routes/api.ts`
(displayable event allow-list), `Log` model (`event`, `text`, `metadata`, `context`, JSONB),
weather via `/api/weather`. The site authenticates humans by session; devices need their own credential.

## 1. Pairing (LOT API connector)
1. User opens Settings → Devices → "Pair pager". Site issues 8-char code (TTL 10 min).
2. Device (first boot, BLE/Wi-Fi provisioning) `POST /api/device/pair {code, hw_id, fw}`.
3. Server returns long-lived **device token** (stored hashed, revocable). Bound to one `userId`.

## 2. Endpoints (all `Authorization: Bearer <device-token>`, TLS only)
| Method | Path | Purpose |
|---|---|---|
| POST | /api/device/pair | exchange code for token |
| GET | /api/device/inbox?since=<id> | long-poll (30 s) for notifications |
| POST | /api/device/ack | `{id, shown_at}` delivered/read |
| POST | /api/device/event | button press etc. → creates Log row |
| POST | /api/device/telemetry | weather/battery batch (every 5–15 min) |
| POST | /api/device/capture | camera JPEG (multipart), rate-limited |

Later upgrade: WebSocket `/api/device/ws` to replace long-poll.

## 3. Notification payload (AI site → pager)
```json
{"id":"n_123","ts":"2026-10-01T09:00:00Z","priority":"normal|urgent",
 "text":"Coffee time!","ttl_s":3600,"alert":"buzz|silent","source":"lot_ai"}
```
Text max 64 chars ×2 lines on 240×240 screen. Generated by scheduled jobs / AI engine
(see `src/server/scheduled-jobs.ts`), queued in a new `device_notifications` table.

## 4. Button "COPY" → Log tab
`POST /api/device/event {"type":"copy","hw_id":"...","ts":"...","notification_id":"n_123"}`
→ server writes `Log{event:'device_copy', text:'COPY ← LOT PAGER', metadata:{hw_id,notification_id,battery}}`
and **must add `'device_copy'` (and `'device_capture'`, `'device_telemetry'`) to the `displayableEvents`
list in `GET /api/logs`** or it will not show in the Log tab.
Semantics: press while a notification is shown = copy that text to the user's Log/clipboard;
press idle = log a bare COPY signal. Debounce 300 ms; offline presses queue in flash (max 200) and replay.

## 5. Security
Device token scoped to `device:*` only; per-token rate limits; JPEG never stored without opt-in;
Wi-Fi creds only in NVS encrypted partition; signed OTA (ESP32 secure boot v2). Threat model: lost device → revoke token in Settings.
