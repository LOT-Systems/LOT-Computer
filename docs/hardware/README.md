## 3. Hard engineering conflicts (decide before PCB spin)
1. **Height.** Stack-up: shell walls 2×0.6 + display 2.1 + PCB 0.8 + Qi coil/ferrite 0.5 + LiPo 2.0–3.0 + camera (OV2640 module ≥ 3–4 mm, bare-die CSP ~2.5) ≈ **8–9 mm**. 5 mm needs no-battery or a ~1 mm cell. **Decision: v1 = 8 mm; v2 target 6 mm.** (Alt: keep 5 mm and drop to a USB-C powered puck — rejected.)
2. **Wireless charging vs. steel.** Eddy currents kill Qi through 316L. Options: (a) flush zirconia/glass disc Ø22 mm inset in the polished face, over the coil — **recommended**, stays "flat silver"; (b) charge from the glass face only; (c) pogo-pin dock (fallback for EVT, 2 pins). Mirror face then has one dark disc; brand to approve.
3. **RF.** Steel shell shields Wi-Fi. Antenna must radiate through the glass window or a plastic/ceramic gap; use an external-antenna ESP32-S3 module + U.FL to a flex antenna behind the glass, or ceramic chip antenna at the window edge. Plan an antenna test at EVT.
4. **Camera + privacy.** Always-on-off hardware indicator and a button gesture for capture; no silent capture. Images stay on-device unless the user presses a capture gesture.
5. **Auth.** Backend auth is cookie-JWT only; devices need a token scheme (new table + routes). Not built yet.

## 4. Architecture
```
LOT site (Fastify/Postgres)            Device (ESP32-S3, 316L body)
 scheduled-jobs / AI  --notify-->  Device API  <==TLS WebSocket==>  firmware
 Log tab  <--hw.copy / hw.sensor--  /api/device/*                  screen · button · camera · BME688 · BMI270
```
Transport: WSS with HTTPS polling fallback (deep-sleep wake every 5 min); details in the spec.
