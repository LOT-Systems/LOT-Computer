# LOT-SR-20261014-01 — LOT® Email v1

**Date:** 2026-10-14 · **Branch:** claude/determined-turing-l9vrzg · **Status:** BUILT, NOT BUILD-VERIFIED (see Checks)

## Mission
Simplest LOT® Email: compose in Log with `/email to Hitomi`, new messages appear in Sync, integrated with Sync chat and Cohort/Community.

## Design (smallest thing that works)
| Layer | Change |
|---|---|
| DB | `lot_emails` table (sender, receiver, subject ≤200, body ≤5000, readAt). Migration `20261014120000_create-lot-emails.cjs` (idempotent `IF NOT EXISTS`). |
| Model | `src/server/models/lot-email.ts`, registered in `models/index.ts`; `LotEmail` type in `shared/types`. |
| API | `POST /api/mail` {to, subject?, body} · `GET /api/mail` (inbox, unread count) · `POST /api/mail/:id/read`. |
| Realtime | SSE event `lot_email`, delivered only to the addressee (`/sync` switch). |
| Log | New trigger `email-compose` (`/email`, `/mail`) in `logTriggers.ts`; `EmailCompose.tsx` block opens in Log, `TO` auto-follows the name typed after `/email to`; Send / Close. Listed in `/system` help. |
| Sync | MAIL section above chat: sender, subject, unread dot (●), `N NEW` counter, click to expand + mark read. Refreshes live on `lot_email`. |
| Audit | `email_sent` Log event (metadata: emailId, receiverId) for social-interaction tracking. |

## Community / Cohort integration
- Sending and reading require Community tags (Admin, R&D, Usership, Onyx, Legacy) — same gate as Sync chat.
- Recipient resolved by first name or full name, case-insensitive, **Community members only**.
- Name collision: same-cohort member (same city + country, the signal used by `/api/cohorts`) wins; if still ambiguous, API returns 409 with candidate full names.
