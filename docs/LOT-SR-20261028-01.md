## PROGRAM COVERAGE

**Widgets wiring / data storing.** `System.tsx` composes ~35 widgets. Every pro-layout widget is inside a named `WidgetErrorBoundary` (isolation OK; Retry button works). Server data comes through `queries.ts` react-query hooks with sensible `staleTime` (2–60 min); stats hooks poll at 120 s with `refetchIntervalInBackground: false`. `SystemPulseWidget` polls every 10 s but pauses when the tab is hidden or the route is inactive, and `/api/system/pulse` is server-cached for 5 s. Local state lives in nanostores and localStorage (planner, recipe, intentions, self-care, pulse dismissal).

**LOT® AI · System tab · Portrait.** System tab "Astrology" Block cycles Astrology → Psychology → My Journey → Biofield views; Psychology/Journey read `useProfile` (`/api/user-profile`: archetype, core values, cohort, awareness index), Biofield reads the intention engine and physiological cohort. Wiring present. Portrait page itself was not deep-scanned this run.

**QIE · Memory · Story.** `QuantumEngineWidgets` (lazy-mounted) reads the intention engine store plus server profile. `MemoryWidget` uses `useMemory` (10 min stale). `NarrativeWidget` / `GoalJourneyWidget` use `useNarrative` / `useGoalProgression`. Intentions and Self-care receive QIE "reason" strings via localStorage hand-off keys (`intentions-quantum-reason`, `selfcare-quantum-reason`) — works, but is an implicit channel; a store would be cleaner.

**Context sync → Log (military-comms style).** Present: System tab shows time, weather (sky, temp, sunrise/sunset), astrology, users online/total. Only 4 widget event types are written to the Log from the client (`self_care_complete`, `self_care_skip`, `plan_set`, `calendar_entry`) plus check-ins/memory via their own mutations. **No widget attaches a shared context stamp (time · weather · users online) to its Log entry.** Server-side `getLogContext(req.user)` does this for some routes (e.g. cosmic-update). Proposal (not built): a one-line SITREP stamp `[HH:MM · sky · temp · N online]` added to widget-originated Log entries so the Log reads like a comms journal. Needs a format decision.

**Monk-lifestyle / LOT® AI as transparency layer.** Existing pieces fit it: fasting-aware Recipe widget, Breathe, Self-care moments with 3 h cooldown, Interventions. The F4 usage log gives the user an inspectable record of what the interface did — the transparency half. A user-facing "what the system recorded about me" view is not built.

**15-month reveal.** Two mechanisms exist and they are not the same thing: (a) `MonthlyPulseWidget` — calendar-month milestone messages (now 1–15, Usership only); (b) `interfaceEvolution.ts` — density/unlocks driven by *mastery* (level, visualRefinement), explicitly "earned through engagement, not just time". **No month-indexed 15-step UI build-up schedule exists in code**; there are no month 1–15 feature gates. If a strict calendar schedule is intended, it needs a spec (which widget appears in which month).

**Lag test.** Not executed (no browser/DB in this environment). Static indicators only: mount-time instrumentation already exists (`[Perf]` warn >50 ms, `window.__LOT_WIDGET_PERF__`), and F4 now persists it. Button/sound debounce: sound toggle has a 300 ms guard; Breathe runs a 100 ms state tick only while on. Recommended next run: Playwright against a seeded local instance reading `__LOT_WIDGET_PERF__` and `__LOT_WIDGET_USAGE__()`.
