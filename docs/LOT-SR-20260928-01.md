## DECISION

```
Simplest LOT Email = zero new backend surface. Reuse the ChatMessage model
and POST /chat-messages route verbatim; format the composed text as an
envelope readout and resolve the recipient name against the user's own
/api/cohorts matches (the same data LOT Community/CohortConnectWidget
already uses). No migration, no new model, no new route, no new SSE event
— the message rides the existing chat_message pipeline into Sync.
```

## FLOW

```
1. Operator types  "/email to Hitomi thanks for the cohort intro"  in Log.
2. logTriggers detects the new 'lot-email' trigger (whole-token /email match).
3. Logs.tsx parses recipient "Hitomi" + body "thanks for the cohort intro".
4. Recipient resolved against the operator's live /api/cohorts matches.
5. Message posted through the existing POST /chat-messages endpoint —
   same auth, same suspension checks, same Log audit trail as any other
   Sync post (server already writes a chat_message Log event for pattern
   analysis — no change needed there either).
6. sync.emit('chat_message', ...) fires as normal → every connected
   operator's Sync (Lot Chat) view receives it live via SSE.
7. Log view shows a confirmation readout: dispatch + resolved recipient +
   cohort-match confidence (or "unverified" if the name isn't a live
   LOT Community cohort connection).
```
