## INTAKE
Scheduled task: make the Calendar widget reliable — track time, log to Log,
military-grade event notifications, keep the minimalist UI.

## BASELINE
Widget stored date-only entries (`calendar_entry`). No time, no alerts, no
acknowledgement, no dedupe. Entry identity was array index.

## BUILD
| File | Change |
|---|---|
| `src/client/utils/calendar.ts` (new) | Pure alert logic: `entryDueAt`, `currentStage`, `formatCountdown`. Stages T-15 → T-05 → NOW → OVERDUE (expires 120 min past due). |
| `src/client/components/CalendarWidget.tsx` | Optional `HH:mm` time on entries; stable `id` from log id; 1 s clock; live alert banner (`T-04:32 · T-05 · CALL 10:00 · text [ACK]`, pulse at NOW/OVERDUE); each stage fires once and logs `calendar_alert`; `[ACK]` logs `calendar_done` and clears banner; done entries struck through in the list; opt-in `Alerts: ON/OFF` toggle for browser system notifications (permission only requested on click). |

## RELIABILITY DESIGN
- Dedupe: fired stages are read back from logs (`entryId:stage`), plus an in-flight ref, so refetch lag or a second device does not double-fire.
- Late page load fires only the current stage (earlier ones are suppressed), never a burst.
- Alerts stop escalating 120 min past due; ACK'd entries never alert.
- Untimed entries behave exactly as before (backward compatible).
