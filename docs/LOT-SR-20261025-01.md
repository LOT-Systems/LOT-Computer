## 5. COMPONENT QUALITY — STATUS PAGE UPGRADE

### Problem

`StatusPage.tsx` (271 lines) used a flat `Block` list with plain text characters (`✓`/`✕`) and no visual hierarchy differentiating the overall system state from individual component checks. For a top-tier product site, the status page is a trust anchor — it should communicate confidence immediately.

### Changes

```
FILE: src/client/components/StatusPage.tsx
BEFORE: 271 lines  →  AFTER: 280 lines
```

**New elements:**

| Element | Description |
|---------|-------------|
| `StatusDot` | Animated pulsing dot — green/amber/red/grey per status. Uses `@keyframes lot-ping` inline — no external dependency. |
| `CheckRow` | Component check as a horizontal row with status dot, name, state label, and response time — replaces `Block` list. |
| `RefreshBar` | 2-minute countdown progress bar (1px tall, acc/18 fill, animates linearly) + "Refresh now" shortcut text button. |
| Overall banner | Prominent bordered panel: dot + status text + relative timestamp + version/env — first thing the eye reads. |
| Memory Engine section | Redesigned as a clean table — dot for availability, quota fraction display. |
| `useRelativeTime` | Live "X minutes ago" tick every 15s — more natural than absolute timestamps for status pages. |
| `useRefreshCountdown` | Drives both the progress bar and the "Refreshes in Ns" label. Resets cleanly on each fetch. |
| Section labels | 11px / `tracking-widest` / `uppercase` — `COMPONENTS`, `MEMORY ENGINE` — clear section identity. |
| Footer | Reduced to 12px text-acc/25 — build date + cache TTL note, never competes visually. |

**Design language preserved:**
- All spacing in multiples of 8px (Tailwind scale)
- `text-acc/X` opacity convention
- `border-acc/[0.12]` subtle borders
- `rounded-[4px]` consistent radius
- No external icon library — only CSS
- `Page` / `GhostButton` / `Button` components unchanged
- Dark mode compatible via CSS variables

**TypeScript**: zero new errors. `relativeTime` plugin from `dayjs` — already a project dependency.
