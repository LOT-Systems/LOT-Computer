# LOT-SR-20261015-01 — LOT® Mail v1 (simplest email system)

Date: 2026-10-15 · Branch: `claude/determined-turing-qa63s6` · Mode: scheduled session

## Brief
Simplest LOT® Email system in LOT® style. Compose in Log with `/email to Hitomi.`; new messages appear in Sync; integrate with Sync chat and Cohort (community) connections.

## What shipped
| Layer | Change |
|---|---|
| DB | `migrations/20261015120000_add-mails.cjs` — `mails` table (sender, receiver, subject, body, replyToId, readAt) + 2 indexes. Idempotent (`IF NOT EXISTS`). |
| Server | `models/mail.ts`; `routes/api.ts`: `GET /api/mail` (inbox, sent, unread), `GET /api/mail/recipients?q=` (name → members), `POST /api/mail`, `POST /api/mail/read`; SSE event `mail` delivered **only to the receiver**. |
| Access | Same gate as Sync chat: Admin / RND / Usership / Onyx / Legacy; Suspended blocked. Recipient must also be eligible. Self-mail rejected. Body ≤ 10 000 chars, subject ≤ 120 (defaults to first line). |
| Log | `/email to Name.` (alias `/mail`) → `parseEmailCommand` (pure, in `logTriggers.ts`) → **MAIL:** block under the log with TO + body preview + Send. Name resolved server-side; ambiguous names show a picker; unknown names report "No member named". The rest of the log text is the body. Listed in `/system` help. |
| Sync | Sync now has **Chat · Mail** tabs. Mail = Inbox / Sent, unread dot, expand to read (marks read), inline Reply, composer. Real-time arrival via SSE. |
| Nav | `Sync (n)` unread count in the nav; `MailBridge` keeps it live app-wide. |
| Cohort | Cohort Connect widget: new **Email** button on each match → opens Sync > Mail composer pre-addressed (`composeMail` store). Records `cohort_email_initiated` signal. |
| Audit | `mail_sent` log event (metadata only, no body). |

## Verification
- `parseEmailCommand` tested: `/email to Hitomi. Dinner at 8?` → `{to:'Hitomi', body:'Dinner at 8?'}`; multiline and `:` punctuation OK; plain text → `null`.
- `tsc` (client + server configs): 37 errors before and after — **no new type errors**, none in touched files.
- Client bundle not built here (`esr` not installed in this container); **deploy must run `migrations:up` then build**.

## Known gaps / next
1. Not run against a live DB/UI this session — needs a smoke test (send Vadik → Hitomi, check inbox, SSE, reply).
2. Pre-existing: `direct_messages` has **no migration** and the SSE handler does not forward `direct_message` events — DMs likely non-functional in prod. Mail deliberately does not depend on it.
3. v1 is in-app only (no SMTP/Resend outbound). Possible v2: email notification for offline recipients via existing `src/utils/email.ts`.
4. "Cohort Dating" has no dedicated surface in code; integration was done through the Cohort Connect widget (the community match list). Revisit if a dating surface is added.
5. Body trims to one level of whitespace when the command sits mid-text (cosmetic).
6. Mail panel loads `GET /api/mail` for every logged-in user; ineligible accounts get one 403 (no retry).
