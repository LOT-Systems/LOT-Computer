## INTAKE
Design, develop, deploy the simplest LOT® Email: compose in Log with
`/email to Hitomi.`, new messages appear in Sync, integrate with LOT Chat
(Sync) and Cohort Dating through LOT Community.

## DESIGN
One table, one command, one inbox. No SMTP, no attachments, no threads.

| Piece      | Where                                              |
|------------|----------------------------------------------------|
| Compose    | Log: `/email to Hitomi. Subject⏎Body` — Ctrl/Cmd+Enter sends |
| Storage    | `lot_emails` (migration `20261023120000_add-lot-emails.cjs`) |
| API        | `GET /api/emails`, `POST /api/emails`, `POST /api/emails/read` |
| Delivery   | SSE event `email` → recipient's stream only → Sync refetches |
| Read       | Sync: MAIL block above chat (10 latest, click to open, marks read) |
| Reply      | Type `/email to Name.` in Log                      |

Parsing (`src/client/utils/emailCommand.ts`, pure): the period after the name
ends the address; first line after it is the subject, the rest the body (a
single line is both). **Nothing is sent while typing** — only on Ctrl/Cmd+Enter,
with a live `EMAIL:` preview block (TO / SUBJECT / status) under the log.
Re-sending identical text is blocked; editing resets status.

## COMMUNITY INTEGRATION
- **LOT Chat (Sync):** inbox lives in the Sync tab; uses the same SSE bus.
- **LOT Community gate:** sender AND recipient must hold a chat-allowed tag
  (Admin / R&D / Usership / Onyx / Legacy) — same rule as Sync chat.
- **Name resolution:** first name, or "First Last"; case-insensitive; 404 if no
  community member matches; 409 (use full name) if ambiguous — no user list leaked.
- **Cohort Dating:** every send writes a Log event `email_sent` with
  `metadata {emailId, receiverId}` — a directed social signal, parallel to
  existing `direct_message_sent`. This is the *hook only*: no repo module
  consumes it yet (grep found no Cohort Dating server code), so matching
  logic is a follow-up.
