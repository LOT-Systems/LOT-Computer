## 2. ERRORS AND WARNINGS — CODE QUALITY

### 🟡 WARNING — Fastify Logger Disabled in Production

```
FILE  : src/server/server.ts:35
CODE  : logger: false  // Temporarily disable logging for development
```

The Fastify instance is initialized with `logger: false`. This means zero
structured HTTP request/response logging in the production environment. If
errors occur in production, there is no request trail to debug from.
The comment "Temporarily disable logging for development" is misleading since
this same `server.ts` runs in production.

**Recommendation:** Restore structured logging:
```ts
const fastify = Fastify({
  logger: config.env !== 'production' ? true : {
    level: 'warn',
    transport: { target: 'pino-pretty' },
  },
})
```

### 🟡 WARNING — Diagnostic console.log Calls in Production Server

```
FILE  : src/server/server.ts
LINES : 127, 150, 154, 171, 184, 331–334, 338, 343, 346, 354
```

Seventeen `console.log`/`console.error` calls are scattered across server.ts,
including explicitly labeled diagnostic routes:

```
[GLOBAL] Request to: <method> <url>        ← logs every request
[SERVER-STARTUP] Registering /u/ routes!   ← startup noise
🟢 [DIAGNOSTIC] Test route hit!            ← exposed test endpoint
🟢 [API-DIAGNOSTIC] Route hit!             ← exposed diagnostic route
[NOT-FOUND] URL/Method/Headers…            ← 404 verbosity
```

These indicate leftover debug instrumentation that should be removed or
gated behind `config.env !== 'production'`. The diagnostic test routes
(`/u/test-route` implied) may also be reachable in production.

**Recommendation:** Remove all `[DIAGNOSTIC]` and `[API-DIAGNOSTIC]`
console.log calls. Gate `[GLOBAL]`, `[NOT-FOUND]`, and `[SERVER-STARTUP]`
logs under `if (config.env !== 'production')`.

### 🟡 ADVISORY — CSP `unsafe-inline` in script-src

```
FILE  : src/server/server.ts:58
CODE  : "'unsafe-inline'",  // in script-src directive
```

The Content-Security-Policy includes `'unsafe-inline'` in `script-src`, which
allows inline `<script>` execution and defeats XSS protection. This is noted as
an existing concern and should be migrated to nonce-based CSP (fastifyHelmet's
`enableCSPNonces` is already set to `true`, so the infrastructure is in place).
