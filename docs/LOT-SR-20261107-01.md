## 3. WIRING MATRIX

**LOT® AI.** Memory → `POST /api/memory/answer` (server AI, returns `response` + `insight`). Client-side "AI" widgets (AIFeedback, ContextualPrompts, ChatCatalyst, Interventions) are driven by the local QIE state, not an LLM call — correct for privacy, but they should be labelled as such.
**System tab.** All widgets mount from `System.tsx`; ambient blocks (Users online, weather, astrology, breathe, sound) are *display + toggle* only, none are posted to the Log.
**Portrait / personal profile (`Settings.tsx`).** Hosts only `GrowthMilestones` + `BadgeUnlockFeed`. No QIE/Memory/Story widget is wired to the Portrait page. This is the largest wiring gap versus the stated design.
**QIE.** 28 client files call `recordSignal`. Widgets with **no** QIE signal: AngelInvestor, CorporatePlan, DemoDay, Subscribe (commercial, acceptable), plus **CorrelatedIndexes, Evolution, InterfaceEvolution, CosmicUpdate, QuantumSign, MonthlyPulse, Time** (display widgets that never report back — dwell/dismissal is invisible to the engine).
**Memory / Story.** Memory, Narrative, GoalJourney, Intentions, ContextualPrompts, PatternRecognition, QuantumState consume memory/story context; Story generation is server-side (`memory/story-generator.ts`) with no dedicated client widget.

## 6. DATA LOG — WIDGET USAGE (new)

`WidgetErrorBoundary` now keeps a **local-only**, bounded (64 widgets) ledger per widget: `mounts`, `crashes`, `lastMountMs`, `maxMountMs`, `slowMounts (>50 ms)`, `lastSeen`. Writes are debounced (2 s) off the render path.
Read it with `window.__LOT_WIDGET_USAGE__()` or `localStorage['lot_widget_usage_v1']`. Nothing is transmitted; this fits the transparent / monk principle and gives a baseline before any server aggregation.
Existing: `window.__LOT_WIDGET_PERF__` (last mount time per boundary).

## 7. LAG REVIEW (static — no live profiling in this environment)

Not measured: real button/sound latency (no browser session against a live DB). What the code shows:

- `TimeWidget` runs a **1 s** interval always (cheap `Date` check; needed for the hourly chime, including backgrounded tabs). OK.
- `SystemPulseWidget` polls every **10 s** and pauses when the tab is hidden or the route is inactive. OK.
- `SystemProgressWidget` recompute every 60 s, paused off-tab. `System` astrology tick every 15 min, paused off-tab. OK.
- 7 queries refetch every 120 s with `refetchIntervalInBackground:false`. OK.
- `/api/logs` has **no LIMIT** (`queries.ts:136` comment); every widget using `useLogs`/`useLogContext` re-derives on each change. This is the most likely source of real-world lag as logs grow. Recommend server-side windowing.
- Sound toggle has a 300 ms re-entry guard. MicroGame has 36 audio references; audio unlock on first gesture was not verified.
- Several derivations in `System.tsx`/UserMetrics are already memoized (earlier perf commits).
