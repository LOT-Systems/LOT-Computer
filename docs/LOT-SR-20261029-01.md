## INTAKE
Scheduled: continue Calendar widget; minimalist UI; reliable; track time and
log to Log; military-grade event notifications; push .MD report.

## BASELINE
CalendarWidget.tsx: date picker + note/task/call entries logged as `calendar_entry`.
No times, no reminders, no completion, no time tracking. Input was cleared before
the save resolved (text lost on failed save).

## FEATURES
- **Timed entries**: start the text with `HH:mm` (e.g. `14:30 call Bob`). Invalid times (25:00) stay as text. Stored in `metadata.time`; backward compatible with untimed entries.
- **Alerts (terminal style)**: `[T-15]` → `[T-05]` → `[T-00]` (pulses) → `[LATE]` (bold, 60 min window). One line per entry, most urgent stage only, with countdown and `ACK`. ACK silences that stage and all earlier ones; persisted in localStorage so reloads don't re-alert. Optional OS notification once per stage, only if browser permission is already granted (requested after first timed entry is saved).
- **Time tracking**: `Start timer` (free) or `Start` on an entry. Persisted in localStorage by start timestamp, so it survives reload/tab close. `Stop` writes a `calendar_timer` log (`[TIME] label — 25m`, with start/end/seconds). Runs < 60 s are discarded. If the save fails, the timer is restored — tracked time is never lost. Today's total and per-entry minutes shown.
- **Done**: `Done` writes a `calendar_done` log referencing the entry's log id (logs are append-only; completion is an event, not a mutation).
- **Reliability**: entry id = log id; input retained on failed save; double-submit guard; sort by date then time; all localStorage access in try/catch.

- Cannot un-do a Done (append-only logs).
