## SCOPE

Static audit of `src/client` widget wiring, timers, evolution gating and logging, plus a typecheck and a production client build. **Not performed:** no live browser lag test and no real audio/latency measurement. Those need a running app with a database and a user session, which this scheduled container does not have. Lag findings below come from code inspection of timers and render paths, not profiling.

## FINDINGS

### 1. Widget wiring and data storing

- All widget files under `components/` are imported. Two files have **zero importers** (dead code): `AwarenessDashboard.tsx` and `JournalReflection.tsx`. The 2026-07-19 ledger entry records these as intentionally skipped duplicates. They still ship in the source tree.
- 25 `WidgetErrorBoundary` wrappers in `System.tsx`, so a widget crash does not take the page down.
- **22 mounted components never write a signal or a log** (no `recordSignal`, no log POST). They are display-only, and are listed below. That is acceptable for pure displays, but the ones marked ★ hold or derive state worth feeding back to LOT® AI.

  `AIFeedbackWidget`, `AngelInvestorWidget`, `ArchitectWidget`, `BenchmarkWidget`, `CorporatePlanWidget`, `CorrelatedIndexesWidget`, `CosmicUpdateWidget`★, `DemoDayWidget`, `EvolutionWidget`★, `IntegrityWidget`★, `InterfaceEvolutionWidget`★, `MonthlyPulseWidget`★, `QuantumSignWidget`★, `QuantumStateWidget`★, `SignalStreamWidget`, `SubscribeWidget`, `SystemPulseWidget`, `TimeWidget`, `UserMetricsWidget`, `MoodAnalytics`, `FourDimensionalUI`, `FlashDriveManifest`.

- Widgets that do write: 25 call `recordSignal` (Memory, Narrative, Planner, Recipe, Intentions, GoalJourney, Chakra, Cohort, QuantumEngineWidgets and others). 5 post logs (Calendar, ContextualPrompts, Planner, Recipe, SystemProgress).

### 2. Wiring to LOT® AI, System tab, Portrait, QIE, Memory and Story

- System tab: wired through `System.tsx` and all of the above.
- Memory and Story: `MemoryWidget` reads `useMemory/useCreateMemory`, `NarrativeWidget` reads `useNarrative`. Both emit signals, and the server has `utils/memory.ts` and `memory/story-generator.ts`.
- Portrait: the only client references are in `MonthlyPulseWidget`, `Settings` and `CosmicUpdateWidget`. There is **no widget-to-Portrait feed**. Portrait is not a consumer of the usage data.
- QIE: widgets reach the Quantum Intent Engine only through `intentionEngine.recordSignal`. The ★ widgets above bypass it.

### 3. Lag and timers (code inspection)

- Fixed in this push: `Clock`, `MicroCalculator`, `QuantumRandom` (two instances, so 2 ticks/s plus the toggle) ran while the tab was hidden.
- **Still open, no hidden-tab guard:**
  - `utils/breathe.ts` `setInterval(updateState, 100)`: 10 updates/s while enabled.
  - `utils/sound.ts` 10 s context poll.
  - `utils/selfCare.tsx` 60 s check.
  - `QuantumRandomWidget` countdown updater has side effects (`setNumber`, `recordSignal`) inside a `setRemaining` updater. Under React StrictMode that can double-fire. Needs a refactor to a ref or effect.
- Already healthy: `TimeWidget` (1 s, with visibility catch-up), `ChakraErgonomics`, `ContextualPrompts` and `SystemPulse` are all guarded. Query polling is 120 s with `refetchIntervalInBackground: false`.
- `LazyMount` (viewport-deferred mount) is used for only **2 of the System tab widget groups** (`QuantumEngineWidgets` and one in `SystemProgressWidget`). The Biofield group (`QuantumState`, `PatternRecognition`, `AIFeedback`, `SignalStream`, `Integrity`) is mounted eagerly. The manifest lists "Viewport Isolate" as READY and not shipped, so it is the best candidate for load-speed gains.
- `SystemProgressWidget.tsx` is 2,513 lines, the largest widget (the next is 988). It is a code-splitting candidate.

### 4. Load speed

- Main bundle `app.js` is 730 KB raw and 185 KB gzip. Two chunks are 238 KB and 195 KB. Build output is split, but the System tab widgets are all in the static graph. Dynamic `import()` of rarely seen widgets (Investor stack, Benchmark, Architect, Calendar) would cut first paint cost. Not done here because it needs on-device verification.
- Build warns about **duplicate object keys** in `badges.ts`: `elixir_found` and `quarter_drop`. The later key silently overwrites the earlier, so one badge definition in each pair is dead. Needs a human pick of the intended definition.

### 5. 15-month UI reveal

- Gating is **level and score based** (`getFeatureUnlocks` in `utils/interfaceEvolution.ts`, 14 flags such as `level >= 15`, `depth >= 0.33`), not calendar based. Only 5 widgets consume the flags.
- `MonthlyPulseWidget` counts **Month N/12**, not 15. There is no 15-month schedule in code today. Aligning the month ladder to 15 months means choosing which widget appears in which month. That is a product decision, so it is not guessed at here.
- Mapping the existing flags to a month grid (proposal for review):

  | Months | Reveal |
  |---|---|
  | 1–3 | Time, Memory, Planner, Recipe, check-in |
  | 4–6 | Mood analytics, intentions history, themes (`level>=5`) |
  | 7–9 | Narrative, pattern insights, cohort connect |
  | 10–12 | Quantum/Biofield stack, Integrity |
  | 13–15 | Architect, Benchmark, Calendar alerts, exports |

### 6. Log posting ("military self-care" context sync)

- Not implemented. Widgets do not post a combined context line (weather, time, users online) to the Log. `System.tsx` already holds `weather`, `usersOnline`, `usersTotal` and the clock, so one structured SITREP line could be built there. Proposed format: `SITREP 0640Z | SKY clear 12C | ONLINE 41 | WIDGET memory:ack`. This needs a decision on whether it posts automatically or only on user action, given the monk and transparent-lifestyle framing, so it is left for approval.

### 7. Widget usage data log

- Done locally (item 1). It is per device and not yet sent to the server. A server-side aggregate (all LOT® users) would need a new endpoint and a privacy review, so it is not built here.
