# LOT® EMAIL — Session Report · 2026-10-06 · SR-20261006-EMAIL-01

**Branch:** `claude/determined-turing-vah9ha` · **Stage:** v1 (simplest viable)

## Objective
Simplest LOT® Email system in LOT® style: compose in Log with `/email to Hitomi`, new messages appear in Sync, tied to LOT Community and Cohort.

## Built
| Layer | Change |
|---|---|
| DB | `migrations/20261006120000_add-lot-emails.cjs` — table `lot_emails` (sender, receiver, subject, body, readAt) |
| Model | `src/server/models/lot-email.ts`, registered in `models/index.ts`; `LotEmail` type in `shared/types` |
| API | `POST /api/mail` (send by first name), `GET /api/mail` (inbox, 100), `POST /api/mail/:id/read` |
| Log | `/email` trigger + `parseEmailCommand()` in `logTriggers.ts`; ⌘/Ctrl+Enter sends; `EMAIL:` status block; listed in `/system` help |
| Sync | Email inbox above chat: unread dot `●`, click to expand/mark read, live refresh via SSE `lot_email` |

## Usage
```
/email to Hitomi: lunch at 1?
```
or
```
/email to Hitomi
Message body, any number of lines.
```
Then press ⌘/Ctrl+Enter. Recipient sees it in Sync. Use `First Last:` form to disambiguate (`409` on duplicate first names).

## Design decisions
- **Own table** rather than overloading `direct_messages` (keeps chat DMs and mail separate; allows subject/read state).
- **SSE is broadcast** in this codebase, so `lot_email` events carry no body — only an id/receiver ping; clients refetch the private inbox.
- **Community scope:** recipients are LOT members (non-suspended users); self-mail excluded.

## Not verified
