## DESIGN — THE SIMPLEST LOT® EMAIL

```
ONE TABLE   lot_emails (id, senderId, receiverId, body, source, readAt, timestamps)
ONE VERB    write a letter to an operator by name
THREE DOORS Log  (/email to Hitomi)  ·  Sync (Reply)  ·  Cohort (Send email)
ONE INBOX   Sync → MAIL block above chat, live over SSE
NO          subjects, threads, CC, attachments, external SMTP
```

### Compose in Log

```
/email to Hitomi
Coffee tomorrow at 9?
```

Also accepted: `/email to Hitomi: Coffee at 9?` · `/email Hitomi Tanaka — hi` · `/mail …`.
A letter ends at the next slash-command line or the end of the log.

Under the editor an `EMAIL:` block appears (same Block style as SCAN / PHYS / FAST):

```
TO              HITOMI T · TOKYO
LENGTH          21/4000
DELIVERY        SYNC
[Send]          SENT 14:32 → HITOMI T
```

Sending is an explicit **Send** click — the Log autosaves on every keystroke, so a
keystroke trigger would fire on `/email t…`. Name is resolved (debounced 400 ms);
when several operators match, each appears as a button to pick. Sent letters are
remembered locally so the same letter can't be sent twice from the same log.
`/system` help now lists `/email to [name]`.

### Receive in Sync

`MAIL · 2 NEW` header, newest first, unread marked `•`. Click to open (marks read),
**Reply** opens an inline composer. New letters arrive live via SSE event
`lot_email`, delivered only to the addressed operator. The MAIL block is visible
to **every** operator — the chat tag-gate still applies to chat only.

### Cohort Dating / LOT Community

Cohort Connect member card: **Send message → Send email**. It sets
`stores.emailDraft` and opens Sync with a letter addressed to that member
(`source: 'cohort'`). The recipient sees `via Cohort` on the opened letter, and
replies keep the cohort source.

### API

```
GET  /api/emails                    → { inbox[50], sent[20], unread }
GET  /api/emails/recipients?q=Name  → { candidates[≤5] }
POST /api/emails                    { to | receiverId, body, source: log|sync|cohort }
                                    200 letter · 400 empty/too long · 403 suspended
                                    404 NO OPERATOR FOUND · 409 MULTIPLE MATCH
                                    429 rate limit (30/h)
POST /api/emails/:id/read           receiver only
```

Guards: no self-mail, suspended senders blocked, suspended recipients unreachable,
suspended senders hidden from inboxes, SSE never leaks letters to other operators.

## DOCTRINE

1. In a live-saving editor, a command that has side effects outside the log needs an explicit confirm — never fire on keystroke.
2. Prefer a new small table with its own migration over reviving a model whose table was never migrated.
3. Mail follows identity, not tags: everyone can receive; only chat stays gated.
