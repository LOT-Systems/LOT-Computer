## 1. Product in one paragraph

A 40 × 40 mm flat, silver, two-part stainless-steel pager-computer. Back: polished stainless mirror. Front: small screen, camera, one button. It receives short autonomous notifications ("Coffee time!") generated by the AI on lot-systems.com, senses weather/air locally, and its single button ("Copy") sends a signal back to the site's **Log** tab. Charges wirelessly. Ships with PDF manuals.

## 3. Architecture

```
 LOT site AI ──► notification queue ──► GET /api/device/inbox ──► [ESP32-S3] ──► screen
                                                                     │  ▲
   Log tab  ◄── Log row (event=device.copy) ◄── POST /api/device/event┘  └ button / camera / BME688
```

- **MCU:** ESP32-S3 module (Wi-Fi + BLE, camera interface, USB-C DFU for bring-up). Proto board: Waveshare ESP32-S3-LCD-1.28 (round 240×240, ETA6096 charger) — https://waveshare.com/ESP32-S3-LCD-1.28.htm (VERIFIED). It has no camera or Qi, so it is only a firmware/API bring-up board.
- **Screen:** simple, low-power, 1.3–1.5" class, notification text only. OLED saves thickness; IPS saves daylight legibility — decide on EVT.
- **Power:** thin LiPo ~150–250 mAh (ESTIMATE; battery thickness is the stack driver), fuel gauge, Qi RX.

## 5. LOT API connector (proposed — not yet in repo)

Repo check: no device endpoints exist today (`/logs`, `/live-message`, `/weather` exist in `src/server/routes/api.ts`).

| Endpoint | Purpose |
|---|---|
| `POST /api/device/pair` | One-time code from Settings → device token |
| `GET /api/device/inbox?since=` | Pending notifications `{id, text, ttl, priority}` |
| `POST /api/device/ack` | Delivered/dismissed |
| `POST /api/device/event` | `{type:"copy", text, deviceId, ts, sensors?}` → Log row, shown in Log tab |
| `POST /api/device/telemetry` | BME688 readings (opt-in) |
| `POST /api/device/photo` | Camera upload (opt-in, explicit) |

Security: per-device revocable token, TLS, rate limit, no secrets in firmware image, signed OTA. Needs a `Device` model + migration (`migrations/`).

## 6. Risks (ranked)

- **R1 — 5 mm height.** Stack: two 0.6 mm steel walls (1.2) + display (~1.5–2.5) + PCB (0.8) + battery (~2.5) + camera (≥2.5–4) > 5 mm. Cannot all fit. Mitigate: 8 mm EVT; thinner display; flex PCB; camera side-by-side not stacked.
- **R2 — Steel blocks Qi and RF.** Stainless shields wireless charging (eddy currents) and degrades Wi-Fi/BLE. Needs a non-metal window: e.g. ceramic/glass insert in the back plate over the coil (breaks "one full polished side"), or charge via the front. **S-2 decision required.** Antenna keep-out + plastic/ceramic window also needed on front.
- **R3 — "Made in the USA".** Repo brand header claims Made in the USA; PCBWay is China-based. Don't use that marking on the device without legal review.
- **R4 — Compliance.** FCC/CE (radio, Qi), UN38.3 battery, RoHS; 100 units sold = certification cost (ESTIMATE $5–15k). Use a pre-certified ESP32 module to reduce.
- **R5 — Camera privacy.** Autonomous AI + camera needs visible indicator and explicit capture.
- **R6 — Battery life** with polling Wi-Fi: design for deep-sleep wake on interval + push via BLE phone relay in v2.
