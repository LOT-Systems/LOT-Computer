# LOT® LOG COMMAND SYSTEM — `/system` · `/story`
**CLASS:** INTERNAL // ENGINEERING  **S-2:** VADIK MARMELADOV  **DATE:** 2026-09-29  **REF:** LOT-SR-20260929-01

---

## 1. PURPOSE

The Log is a passive AI surface. The operator writes; no prompts, no questions. Every entry is stored with the context captured at write time (temperature, humidity, sky, city, time zone, moon phase, zodiac hour). Two commands expose the machine on demand without breaking that passivity:

| Command | Effect |
|---------|--------|
| `/system` | Prints every Log command, grouped, generated from one registry |
| `/story [day\|week\|month\|year]` | Prints a compressed story of the chosen window, written by the AI from a deterministic digest of the operator's own data |

## 2. LOOP POSITION

```
LOT User data (Log rows + context metadata)
   -> DIGEST            src/shared/utils/storyDigest.ts   deterministic compression, no LLM
   -> QIE INTENT LAYER  operator state (energy/clarity/alignment) + user index ride along
   -> AI VENDOR         Together AI  (aiEngineManager.getEngine('together'))
   -> LOT PERSONALIZED DATA STORED   Log row  event='generated_story'  metadata.period + digest summary
```

Design rule: **the model narrates, it does not measure.** All numbers, days, moods and places come from the digest; the prompt forbids invention. If the vendor fails, `composeDigestStory()` returns a true, deterministic story built from the same digest (never an apology string).

## 4. `/system`

Output is generated by `renderSystemHelp()` from `LOG_COMMANDS`, grouped `MEMORY · STATE · PROTOCOL · DEVICE · SYSTEM`. Row format contract with the client renderer: a line beginning `/` is `"/name [args]"` + 2+ spaces + description; other non-empty lines are headers. **To add a command: add one registry row and one rule in `logTriggers.ts`; the test fails if they diverge.**

## 5. `/story`

### 5.1 Periods

| Input | Window | Word budget | Max tokens |
|-------|--------|-------------|-----------|
| `/story` or `📖` | 3 days (`now`) | 100–160 | 400 |
| `/story day` | 1 day | 100–160 | 400 |
| `/story week` | 7 days | 140–220 | 400 |
| `/story month` | 30 days | 180–260 | 512 |
| `/story year` | 365 days | 220–320 | 640 |

Aliases: `today/daily`, `weekly`, `monthly`, `yearly/annual`. An unrecognised word after `/story` is treated as note text, not a period (`/story weekend` → `now`).

**Grace window.** The trigger fires as soon as `/story` is typed, so the client waits 1.2 s, re-reads the latest text, then parses the period. Type `/story week` and pause.

### 5.2 Digest fields

`entryCount, activeDays, streakDays` · `dayPart` (night/morning/afternoon/evening, in the operator's time zone) · `moods, topMood` · `cities` · `weather.avgTempC` (Kelvin→°C), `weather.dominant` · `moon` · `spikeDays` (≥3 entries and ≥2× window mean) · `paceShift` (second half ≥2× busier/quieter, needs ≥6 entries) · `excerpts` (capped 6/10/12 by window) · `rank`.

Journal material = events `log_entry` and `journal` with non-blank text. Blank/whitespace rows are excluded. Server row cap: 500 (2000 for `year`).

### 5.3 Arcade evolution

Consistency is a game-like marker, never pressure. Lifetime journal entries map to a level:

| Lvl | Title | Entries |
|-----|-------|---------|
| 1 | BOOT | 0 |
| 2 | SIGNAL | 5 |
| 3 | OPERATOR | 20 |
| 4 | NAVIGATOR | 60 |
| 5 | ARCHITECT | 150 |
| 6 | CARTOGRAPHER | 400 |
| 7 | LEGACY | 1000 |

The story mentions the level once, lightly. The stored story row keeps `metadata.digest.rank` so future widgets can chart evolution. Level titles are provisional and independent of the badge codex (docs/badges/).

## 6. SECURITY & PRIVACY POSTURE

- Usership tag required (403 otherwise) — unchanged.
- Rate limit 5/min — unchanged.
- Only the requesting user's rows are queried (`userId` scoped).
- The vendor prompt receives excerpts (≤160 chars each), aggregate context and operator state; no email, no user id.
- Stored row keeps a digest *summary*, not the excerpts.
