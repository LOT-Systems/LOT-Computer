--------------------------------------------------------------------------------
01 // PURPOSE
--------------------------------------------------------------------------------
The Log is a passive AI surface: the operator writes, never prompts. Slash
commands are the ONLY explicit control channel inside it. Two matter most for
the compression loop:

  /system   print every command (grouped), plus Arcade standing
  /story    compress the operator's day / week / month / year into a story

Doctrine: LOG -> OBSERVE -> COMPRESS -> ASK -> COMPRESS AGAIN
(see docs/corporate/LOT-AI-PRODUCT-BRIEF.md). /story is the COMPRESS step made
user-invokable; the scheduled weekly Story-Report (QIE Job 24) is the same
step made autonomous.

--------------------------------------------------------------------------------
02 // DATA FLOW
--------------------------------------------------------------------------------
  LOT User data (Log rows + per-row context meta: weather, humidity, city)
        |
        v
  StoryDigest            src/shared/utils/storyCompression.ts   (pure)
        |   counts, moods, environment, spikes, <=6 excerpts, Arcade rank
        v
  LOT Quantum Intent Engine   operator state + user index (client getUserState)
        |
        v
  AI vendor processor    Together AI via aiEngineManager.getEngine('together')
        |   receives the DIGEST ONLY — never raw history
        v
  LOT personalized data  Log row event='generated_story' (metadata: period,
                         arcade, digest summary, quantumState)

FAILURE MODE: if the vendor call throws, the SERVER returns buildLocalStory(digest)
— a deterministic second-person story from the same digest. /story always
answers with real data; it never returns a canned placeholder.

03 // COMMAND REGISTRY (/system)
--------------------------------------------------------------------------------
  Detector   src/client/utils/logTriggers.ts   WHAT fires (keywords/emojis)
  Registry   src/client/utils/logCommands.ts   WHAT /system PRINTS (single source)
  Handlers   src/client/components/Logs.tsx    WHAT happens

/system output is generated by buildSystemHelp(); it is no longer a hand-typed
list in Logs.tsx. Groups: MEMORY, ENGINE, RITUAL, ENVIRONMENT, NAVIGATION.
Rendering contract: a line beginning "/" is a command row (usage, 2+ spaces,
description); any other line is a section label.

KNOWN GAP (recorded, not hidden): '/sil' is detected by logTriggers but has no
handler in Logs.tsx. It is deliberately NOT advertised in /system until wired.

LOCKSTEP TEST: scripts/tests/test-story-compression.ts probes every wired

04 // /story SPECIFICATION
--------------------------------------------------------------------------------
SYNTAX      /story [day|week|month|year]      default: week; "today" = day;
            plural accepted ("/story years"); "/story weekend" is NOT a period.
CLIENT      parseStoryPeriod(text), stripStoryCommand(text) -> POST /api/story
            { logText, period, quantumState, userIndex }
SERVER      POST /api/story   rate limit 5/min; Usership tag required (403 else)
WINDOW      day=1d week=7d month=30d year=365d, rolling back from now (UTC)
SOURCE      last 1000 Log rows for the user; machine rows
            (generated_story, generated_prayer) are excluded from all counts
RESPONSE    { story, logId, period, arcade }
PERSISTED   Log event='generated_story', metadata{story, logText, period,
            arcade, digest{entries,checkins,activeDays,streakDays,spikes},
            quantumState, timestamp}
UI          📖 block: "<PERIOD> · LV n TITLE · XP · N TO NEXT" then story text;
            story is also appended to the entry text (existing behavior).

DIGEST HEURISTICS (deliberately simple and explainable; no ML):
  volume spike   a day with >=3 records AND >=2x the mean records/active day
                 (period != day, >=3 active days)
  mood shift     most frequent emotional_checkin mood in first half of the
                 window differs from the second half (>=4 mood check-ins)
  quiet gap      longest silence between consecutive records >= 2 days
  streak         consecutive UTC active days ending today (today may be empty)
  environment    mean temperature (stored deg F -> C), mean humidity, top 3 cities

PROMPT RULES   second person; digest facts only; no invention; spikes named
               with compassion; one forward-looking closing sentence; self-care,
               not medicine — no diagnoses.

--------------------------------------------------------------------------------
05 // PRIVACY
--------------------------------------------------------------------------------
- Vendor receives: counts, mood labels, environment averages, <=6 excerpts of
  <=160 chars, Arcade rank, the operator's current /story line (<=500 chars).
- Vendor does NOT receive: full log history, other users' data, email, user id.
- No photo / audio is captured by any part of this system.
- Excerpts are user text; they leave the server to the vendor on /story only.

--------------------------------------------------------------------------------
06 // ARCADE (gamified evolution)
--------------------------------------------------------------------------------
The self-care product is also an arcade: consistency is score. XP is computed
from LIFETIME rows (not just the window) so rank never drops on /story day.

  XP = 10 x journal entry + 5 x check-in + 20 x distinct active day
  (window digests add 5 x streak day only to the window-local fallback figure)

  LV  TITLE        XP at
  1   ROOKIE       0
  2   OPERATOR     100
  3   SIGNALMAN    300
  4   NAVIGATOR    700
  5   ARCHITECT    1500
  6   MAINFRAME    3000
  7   QUANTUM      6000

Display: /system prints the last known standing under "ARCADE" (cached in
localStorage key lot_arcade_rank after any /story; absent before first /story).
This rank is a LOG-ACTIVITY ladder and is independent of the Badge Codex
(docs/badges/) and Interface Evolution levels (docs/technical/INTERFACE_EVOLUTION.md);
unifying them is an open item (see 08).
