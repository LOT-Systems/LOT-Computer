## 1. PURPOSE

The Log is a passive AI interface: the operator writes entries with no prompts
or questions. Each entry is stored with its context snapshot (weather, city,
time, moon/astrology). Slash commands are the *only* active surface inside the
Log. They are typed inline, never required, and never interrupt writing.

Two commands carry the LOT AI loop:

| Command | Output |
|---------|--------|
| `/system` | Full command list, grouped by category |
| `/story [day\|week\|month\|year]` | Compressed story of the period (default `week`) |
| `/rank` | Arcade evolution: rank, level, XP, streak |

## 2. PIPELINE

```
LOT User data (logs + context metadata)
   → story-compression.ts      deterministic DIGEST (counts, streak, moods,
                               places, peak day, silence gap, trend)
   → LOT Quantum Intent Engine digest + operator state injected into prompt
   → AI vendor processor       Together AI (generateCompletion, 512 tokens)
   → LOT personalized data     stored as Log event `generated_story`
                               (story, period, source, digest)
```

Doctrine: **the AI narrates, it does not measure.** Every number, date, place
and mood in a story comes from the digest. The prompt forbids facts not in the
digest. If the AI call fails or there is no signal, `composeFallbackStory`
renders the same digest with no AI (`source: "digest"`), so `/story` never
returns an error string in place of the operator's data.

## 4. /system

Generated by `renderSystemHelp()` from `LOG_COMMANDS`. Categories: AI, STATE,
RITUAL, INTERFACE, SYSTEM. Adding a command = add one registry row **and** one
rule in `logTriggers.ts`; a test asserts every registry command appears in the
help. Typing an unknown `/word` for 1.5 s shows a hint
("Did you mean /story?") — silent while the operator is still typing.

## 5. /story

**Periods:** `day` (1d), `week` (7d, default), `month` (30d), `year` (365d).
Aliases: today, daily, weekly, monthly, yearly.

**Timing:** the trigger fires when `/story` is typed; the client waits 1.2 s so
a period can be finished (`/story month`), then reads the latest text.

**Digest fields:** total signals, entries, check-ins, active days, streak
(consecutive UTC days ending today/yesterday), top moods, top places, average
temperature, moon phases, peak day (high), longest silent gap (low), activity
trend (second half vs first half of the window: rising / falling / steady).

**Signal definition:** operator-authored events only (`note`, check-ins,
memory answers). Generated stories, prayers, system snapshots, chat and
empty autosaved notes are excluded — a story never summarises itself.

**Fix of record:** the previous `/story` filtered on events `log_entry` /
`journal`, which the Log tab never writes (it writes `note`). Stories
therefore never saw journal text. Corrected.

**Access:** Usership tag required (unchanged). Rate limit 5/min (unchanged).

**Storage:** `Log` row, event `generated_story`, metadata `{story, period,
source, digest, logText, quantumState, timestamp}` — the compressed layer
later follow-ups and longer-period stories can build on.

## 6. ARCADE (self-care evolution)

Gamified, but in a self-care company: the arcade *reflects* behavior, it does
not reward grinding and **never punishes**.

```
XP = entries×10 + activeDays×25 + checkins×5 + min(streak×2, 400)
Level L requires 50·(L−1)² XP, max level 99
```

| Level | Rank |
|-------|------|
| 1 | RECRUIT |
| 5 | OPERATOR |
| 10 | ADEPT |
| 20 | SPECIALIST |
| 35 | VETERAN |
| 50 | COMMANDER |
| 70 | ARCHITECT |
| 90 | SAGE |

Rules: no decay, no XP loss, missing a day only pauses the streak bonus;
inputs are sanitised (NaN/negative → 0); streak bonus capped at 400 XP.
`/rank` renders the state as a terminal grid (progress bar, XP to next level).
The `/api/story` response also carries the arcade state so the UI can surface
a level-up moment without a second request.

Relationship to existing systems: the 800+ badge codex and streak milestones
(`client/utils/badges.ts`) remain the achievement layer; arcade level is the
continuous progression layer beneath it. Wiring level-ups into badge unlocks
is open work (§8).
