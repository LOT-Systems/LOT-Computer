## INTAKE

Scheduled widget health scan: wiring, UI, lag, load speed, 15-month reveal, usage log, LOT AI / System / Portrait / QIE / Memory / Story wiring, and a "monk-lifestyle" synced status post to the Log.

**Method and limits:** static audit of `src/client` plus `tsc` and a production esbuild. No browser lag test was run: no live server or DB in this environment. The lag section is code-level analysis only and should be confirmed with `window.__LOT_PERF__` on a device.

## 1. WIDGET INVENTORY (System tab, `System.tsx`)

- 40 `*Widget*.tsx` files plus EmotionalCheckIn, SelfCareMoments, EnergyCapacitor, MoodAnalytics and the `stats/*` feed.
- Two layouts: non-paid (Memory, Game, Subscribe, essentials) and paid R&D/Usership (full stack).

- Widgets are either **data containers** (Memory, Planner, Recipe, Calendar, Intentions, Self-care, Check-in: they write logs or stores) or **data displays** (Dashboard, Biofield, Stats stacks: read-only).

## 4. CHANGES

1. `utils/widgetUsage.ts` (new)
   - Local-only, content-free ring buffer (500 events) of widget `mount`, `error` and `interact` events, persisted to localStorage with all access guarded.
   - Nothing the user typed is stored, and nothing is sent to a server.
   - Inspect with `window.__LOT_WIDGET_USAGE__.summary()`.
   - Holds `buildSitrep()`, a pure function that builds the military-comms status block.
2. `ui/WidgetErrorBoundary.tsx`: records `mount` (with ms) and `error` into the usage log.
3. `utils/logTriggers.ts` + `Logs.tsx`: new `/sitrep` (alias `/sync`) command. It renders a SITREP block with synced local time (DTG), link state, operators online/total, weather, 24 h widget activity, faults, slowest mount and top widgets, closing "CLEAN · TRANSPARENT · OUT". Listed in `/system` help.
   - The block is shown, not auto-posted: the user decides what enters their Log.
4. `System.tsx`: `LazyMount` takes a `className` so it can be the stack container and keep flex gaps. Applied to Biofield, Dashboard and Stats stacks.
   - Side effect: `WidgetErrorBoundary` mount timings for these stacks now measure only the container mount.
5. `QuantumRandomWidget.tsx`: ticks pause while the tab is hidden, the countdown moves into a ref, and `recordSignal` is out of the state updater.
6. `MonthlyPulseWidget.tsx`: `MAX_REVEAL_MONTH = 15`, with messages for months 13–15.

## 5. LAG / LOAD ANALYSIS (static)

- Intervals: 20 timer sites audited. All are cleared on unmount except F7. 11 gate on `document.hidden`; F1 added one more.
- Listeners: add/remove are balanced in all components. `stores/layout.ts` and `utils/sse.ts` register at module scope for the app lifetime, which is intended.
- MicroGameWidget (988 lines, 36 sound references) already pauses its loop off-screen via `useActiveViewport`.
- Existing instrumentation: `utils/perf.ts` (INP and long-frame observer) exposes `window.__LOT_PERF__`. `WidgetErrorBoundary` exposes `window.__LOT_WIDGET_PERF__`. Mounts over 50 ms warn in the console.
- **Not measured:** button/sound/control latency on device. Run on a real phone: `__LOT_PERF__.getEntries()` and `__LOT_WIDGET_USAGE__.summary()`.
