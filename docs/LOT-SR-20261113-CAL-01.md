## ACTION — WHAT SHIPPED

### 1. Calendar core — `src/shared/utils/calendar.ts` (new, pure, shared client+server)

```
LIFECYCLE   open ──(T-15, timed only)──▶ prealertAt  → STANDBY bulletin
                 ──(T-00)──────────────▶ firedAt     → ALERT bulletin + Log row
                 ──(+10M)──────────────▶ snoozeUntil set, firedAt cleared (re-arms)
                 ──(DONE / VOID)────────▶ status closed → Log row
ALL-DAY     alert at 09:00 local on the date; overdue only after the day ends
FIRE WINDOW 24h — an alert missed by >24h is shown OVERDUE, never toasted
            (no toast storm after a long absence)
FORMATS     milTime "1430" · DTG "131430J NOV 26" (J = observer local time)
            T-minus "T-02:14" / "T+00:03" / ">99h → T-7D"
LEGACY      old entries (no status/time) load as open/all-day — zero migration
```

### 2. Server — `src/server/routes/api.ts`

| Endpoint | Purpose |
|---|---|
| `GET /api/calendar` | All of the user's `calendar_entry` rows (up to 1000, not age-capped by the 500-row log window), normalized + sorted. Fixes **D1**. |
| `POST /api/calendar/:id/:action` | `prealert · fire · snooze · done · void · reopen`. Alert claims are **atomic**: a conditional `UPDATE … WHERE metadata->>'firedAt' IS NULL` guarantees exactly one ALERT — and exactly one Log row — per due time across tabs and devices. |
| `calendar_alert` event | New Log event (added to the displayable list). Text e.g. `[CAL/ALERT] 131430J NOV 26 · CALL · Dentist`; metadata carries kind, entry ref, lateMin. |
| `PUT /api/logs/:id` | Ownership check added (`log.userId !== req.user.id → 404`). Fixes **D7**. |

DTG in log text is built from the stored local date/time strings, so the server
(UTC) renders exactly what the operator scheduled — no timezone drift.

### 3. Alert engine + bulletins — `src/client/components/CalendarAlerts.tsx` (new)

```
MOUNT       App root (app.tsx), not the System tab — System unmounts when you
            switch tabs, so alerts now fire on every tab.
SCAN        every 15s + on data change + on tab re-focus; refetch feed every 5m.
CLAIM       server-side (see above); in-flight keys prevent double requests;
            network failure → retried on next tick.
CHANNELS    • on-screen bulletin (ALERT persists until ACK; STANDBY self-clears 30s)
            • tab title flag  "▲ ALERT · …"  while unacknowledged
            • browser Notification when tab is hidden (permission requested on
              first timed entry — a user gesture)
            • 3-pip time-signal tone (880/880/1320 Hz) when Sound is On
CONTROLS    ACK · DONE · +10M   ·  ESC acknowledges the top ALERT
STACK       ALERT outranks STANDBY · max 3 visible · "+N QUEUED"
A11Y        role=alert, aria-live=assertive, prefers-reduced-motion honored
```

Bulletin anatomy (monochrome, theme accent only — matches LOT minimalism):

```
┌──────────────────────────────────────────┐
│ ■ LOT/CAL · ALERT              T+00:01   │   ■ blinks 1Hz (steps, no fade)
│ CALL · Call with logistics officer       │
│ DTG 132351J NOV 26                       │
│ ACK   DONE   +10M                        │
└──────────────────────────────────────────┘
```
