### 2.2 Displays (no writes)
AIFeedback, Architect, Benchmark, Calendar (invalidates `/api/logs`), CorrelatedIndexes, CosmicUpdate, CorporatePlan, AngelInvestor, DemoDay, Evolution, Integrity, InterfaceEvolution, MonthlyPulse, QuantumSign, QuantumState, SignalStream, Subscribe, SystemPulse (polls `/api/system/pulse`), Time, UserMetrics.

### 2.3 Wiring to the three destinations
- **LOT® AI / System tab:** `System.tsx` calls `getOptimalWidget()` from the QIE. That call decides whether Self-care or Intentions surfaces. The reason string is handed to the widget through `localStorage` (`selfcare-quantum-reason`, `intentions-quantum-reason`). This works, but it is an implicit channel. A prop or a store field would be safer.
- **Portrait (user profile):** there is no client widget named Portrait. The portrait is assembled on the server from Memory answers (`server/utils/memory.ts`, `story-generator.ts`). The client only surfaces it as copy ("The portrait deepens", `Settings.tsx`, `MonthlyPulseWidget`). The wiring is therefore **Memory widget → `/api/logs` → server portrait/story**. Widgets that don't write to `/api/logs` or the QIE sync (`/api/quantum-intent/sync`) can't influence the portrait.
- **QIE / Memory / Story:** QIE signals persist through `schedulePersist()` (coalesced, off the interaction tick) and sync through `syncToServer()` with a cooldown. This is sound. `recordSignal` keeps 7 days of signals and caps the count, so signal storage is bounded.

## 5. Monk-lifestyle / LOT® AI doctrine and the 15-month reveal

- **Synchronized context.** Weather, local time and users-online all render in the System header. They are not yet bundled into a single "status line" that any interactive widget can attach to the Log. `ContextualPromptsWidget` is the only widget that posts a plain-text line to `/api/logs`, and it doesn't include weather, time or users online.
- **Proposal — "Comms line" (not built).** Add `buildCommsLine({ time, weather, usersOnline, widget, action })` returning a terse military-style string, e.g. `1412 LOCAL · 11C CLEAR · 214 ONLINE · MEMORY ANSWERED · OUT.` Interactive widgets would then call it when posting to `/api/logs`. A log line becomes a verifiable, plain-language record: what was done, when, and in what conditions. That is the transparent-practice record for LOT® AI to read. It needs a decision on the format and on whether weather is stored in the log text.
- **15-month reveal.** The reveal now covers 15 months in `MonthlyPulseWidget`, and it appears only to Usership users. The widget **layout** is not gated by month. Density evolves through `interfaceEvolution.ts` (five levels, from `breathable` to `instrument`), which is driven by mastery metrics, not by account age. No code maps "month N unlocks widget X". If a calendar-based build-up is wanted, the cleanest place is a `monthsSinceJoin → allowed widget set` table consumed in `System.tsx`. This needs a product decision, so none was built.

## 7. Recommendations (not built; need your call)

1. **Platform-wide widget usage log.** Batch the local ledger to a new `POST /api/widget-usage` once per session (on `visibilitychange: hidden`, through `navigator.sendBeacon`). Store counters only. This answers "which widgets are used, and which crash" across LOT® Systems.
2. **Lazy-load heavy, below-the-fold widgets.** `SystemProgressWidget`, `MicroGameWidget` (988 lines), `IntegrityWidget`, `PatternRecognitionWidget` and the investor trio. esbuild `splitting: true` is already enabled, so only `React.lazy` + `Suspense` is missing. Estimated gain: a smaller first-paint bundle. **Measure with `yarn client:js:build:metafile` first.**
3. **One shared `AudioContext`** module with a single unlock-on-first-gesture. All five sound modules would call it (F8).
4. **Replace the `localStorage` reason channel** (`selfcare-quantum-reason`) with a store field.
5. **Wrap `TimeWidget` and `QuantumRandomWidget`** in `WidgetErrorBoundary` in `System.tsx` (lines ~444, ~616) so they also appear in the usage ledger.
6. **Clean up the `MonthlyPulseWidget` timeouts** (F6).
