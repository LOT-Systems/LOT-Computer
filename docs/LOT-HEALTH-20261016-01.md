### Fixes Applied This Session

**1. `tsconfig.json` — Added `ignoreDeprecations: "6.0"`**
```json
"moduleResolution": "Node",
"ignoreDeprecations": "6.0",
```
Silences TypeScript 7.0 deprecation warnings for `baseUrl` and `moduleResolution: Node`.

**2. `src/server/routes/public-api.ts` — Activated `'degraded'` state**
```typescript
// Before
const hasErrors = checks.some((c) => c.status === 'error')
const overall = hasErrors ? 'error' : 'ok'

// After
const errorCount = checks.filter((c) => c.status === 'error').length
const overall: 'ok' | 'degraded' | 'error' =
  errorCount === 0 ? 'ok' :
  errorCount < checks.length ? 'degraded' :
  'error'
```
Partial failures (1–7 of 8 checks failing) now correctly return `'degraded'` instead of the all-or-nothing binary. The frontend already handled this state — the backend logic was not aligned.

**3. `src/client/components/StatusPage.tsx` — Semantic status display**

Replaced ASCII-character status icons with semantic colored dots and a clear overall status badge:

- **Operational:** green dot + `text-green-400` — unmistakably healthy
- **Error:** red dot + `text-red-400` — unmistakably failed
- **Unknown:** muted dot + `text-acc/50` — neutral
- Overall badge: color-coded pill (green/yellow/red) with border, matching the degraded/error/ok states

Error messages now render in `text-red-400/80` instead of generic `text-acc/60`.
