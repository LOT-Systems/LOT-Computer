## 3. FINDINGS

### F1 — HIGH — The 15-month reveal is not implemented
The gates in `interfaceEvolution.ts` are score and level based (`level >= 15`, `depth >= 0.33`, and so on). There is no month index or account-age gate in code. The only "month" artifacts are `MonthlyPulseWidget` and doc mentions. The brief's "month-to-month UI reveal, 15 months" has no source of truth, and nearly the whole widget wall renders on day 1 (see F2).
**Recommendation:** add `getRevealMonth()` (months since `me.createdAt`, capped at 15) and a single `WIDGET_REVEAL` table (widget to first month). Wrap each widget in one `<Reveal widget="…">`. The Section 6 table is a proposed draft.

### F2 — HIGH — Everything mounts on first paint, with no code-splitting
All 39 widgets are statically imported by `System.tsx`, and 37 of 39 are not memoized. Only `QuantumEngineWidgets` is deferred. `esbuild splitting:true` is wasted without dynamic imports.
**Recommendation:** `React.lazy` the heavy and below-fold widgets (`SystemProgress` 2.5k lines, `MicroGame`, `PatternRecognition`, `Integrity`, `CorporatePlan`, `AngelInvestor`, `DemoDay`) inside the existing `LazyMount`. Wrap the 37 un-memoized widgets in `React.memo`. The 15-month reveal (F1) removes most of them from first paint anyway.

### F3 — MEDIUM — 3 render sites sit outside the error boundary
`TimeWidget` (`System.tsx:444`, `:616`) and `QuantumRandomWidget` (`:617`) are bare. `TimeWidget` has an interval. A throw there takes down the whole System tab.
**Recommendation:** wrap them.

### F4 — MEDIUM — No widget-usage data log exists
There is no `trackWidget` / `widgetUsage` anywhere. The server's `os-api.ts` "imbalanced widget usage" check (`:290`, `:701`) infers usage from other data. Only 6 widgets write to the Log: `Calendar`, `ContextualPrompts`, `Planner`, `Recipe`, `SelfCareMoments`, `SystemProgress`.
**Recommendation:** add a small `logWidgetEvent(widget, action, ctx)` helper. It would call `recordSignal('widget', …)` for the QIE, which is already debounced by `schedulePersist`, and batch to the server. The context snapshot (weather, local time, users online, QIE phase) goes in the metadata. Entries read like short military comms lines (see Section 5).

### F5 — MEDIUM — Widget data storage is fragmented
Widget state is spread across `localStorage` keys (`intention-signals` [7-day window], `recentMemoryQuestions`, `memory-error-*`), `sessionStorage` (`answeredMemoryQuestions`), nanostores (`recipeWidget`, `plannerWidget`, `rewardWidgets`, `chakraErgonomics`) and React Query (`/api/memory`, `/api/logs`). Only the Log and Memory persist server-side. Signals older than 7 days are discarded, so any longer-horizon (month-scale) reveal logic needs a server-side counter.

### F6 — LOW — `SystemProgressWidget` interval accounting
A grep found 3 `setInterval` vs 2 `clearInterval`. The third `setInterval` hit is inside a changelog text string (line 691, a prose reference to `clearInterval`) and the real interval at line 1557 is cleaned up. **No leak.** Other widgets are balanced (`add/removeEventListener` counts match everywhere).

### F7 — LOW — Sound and buttons
Sounds (`utils/sound.ts`, `sovietChime.ts`, `sovietGameSounds.ts`, `sovietKeyboard.ts`) are wired from `System`, `Settings`, `About`, and `app.tsx`; no widget component plays sound directly. The button hover was already moved to GPU `::before` opacity (Button Perf, LOT-MANIFEST), which is a good change. No input-latency issue is visible statically, but it is unverified at runtime.

### F8 — INFO — Wiring that is healthy
- Every widget is mounted, and none is imported but unused.
- The QIE signal store throttles localStorage writes (250 ms coalesced) and caps signals.
- `MicroGameWidget` pauses its loop off-screen.
- `useInViewport` has an `IntersectionObserver` fallback.

## 5. MONK / MILITARY-COMMS LOG PROPOSAL (design only)
Interactive widgets post a one-line sync to the Log, with context attached:

```
0814Z // WX 12C CLR // ONLINE 41 // PHASE LUTEAL-EARLY // BREATHE DONE // 3 MIN // SIGNAL STEADY
```

Rules: a fixed field order, UTC time, no filler words, and one line per action. LOT® AI is the only writer of the narrative summary. A daily rollup ("DAY LOG, 7 ACTIONS, 0 BREACHES") feeds Story. The ration, silence, and fast widgets are the monk layer: a widget that does not support the practice (game, calculator) stays hidden until a later month.
