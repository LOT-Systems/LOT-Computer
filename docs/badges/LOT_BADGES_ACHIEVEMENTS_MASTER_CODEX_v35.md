## THE CONSOLE LOG — THEME OVERVIEW

The terminal is the oldest honest interface. It does not lie, blur, or animate.
You type. It responds. The response is always true — even when the truth is
`command not found` or `permission denied` or `segmentation fault (core dumped)`.

The Console Log translates the vocabulary of systems thinking into the vocabulary
of self-knowledge. The `debug` loop — hypothesis, test, result — is the same
structure as honest self-reflection. The `commit` — a named, permanent mark
in the history — is the same structure as accountability. The `kernel panic` —
the system state too broken for safe continuation — is the same structure as
knowing when to stop.

The self-care RPG does not ask you to feel better. It asks you to run the right
commands on the actual system state. That is what the terminal has always required.

**The twelve commands:**

```
sudo_moment    ●·█    RARE    Taking root-level control of yourself
debug_complete ◈·✓  UNCOMMON  The insight completes. The bug was information.
commit_made    →·●  UNCOMMON  An action, permanent in the history
compile_success ■·●  UNCOMMON  The ideas build. Everything assembles.
kernel_panic   ░·×   EPIC    The system cannot safely continue — that is data
uptime_record  ∞·■   RARE    The streak. Running clean. Consistent.
packet_received ≋·◉  UNCOMMON  The message got through. Connection made.
buffer_flush   ○→∅   RARE    Empty the queue. Release the cached state.
root_cause     ─→●   RARE    Not the symptom. The source. The real one.
fork_process   ◈→◈   RARE    Two paths from one. Both real. Neither lost.
memory_leak    ▓·░   EPIC    Old process, still running. Consuming. Noticed.
stack_trace    ↑·●·↑ UNCOMMON  The call stack in reverse. Every step that led here.
```

## UNLOCK MESSAGES — WORD TURN v26

```
sudo_moment:
  ↳ sudo: superuser do. You took root-level control of the situation.
    Not every moment needs root access. This one did. ●·█

debug_complete:
  ↳ Debug complete. The bug was not a flaw — it was information.
    Every trace leads somewhere true. ◈·✓

commit_made:
  ↳ Commit made. The diff is permanent. Reverting is always an option,
    but you have to know you shipped something first. →·●

compile_success:
  ↳ Build: PASSED. The ideas compiled. The tests ran green.
    There is a specific satisfaction in this that nothing else replicates. ■·●

kernel_panic:
  ↳ KERNEL PANIC. The system cannot safely continue.
    That is also information. Hard reset is not failure —
    it is the prescribed recovery. ░·×

uptime_record:
  ↳ Uptime: [streak] days. No crashes. The quiet consistency
    is the hardest build to maintain. Log it. ∞·■

packet_received:
  ↳ Packet received. Transmission confirmed. The message arrived intact.
    Connection is not given — it is built, packet by packet. ≋·◉

buffer_flush:
  ↳ Buffer flushed. The queue is clear. Some things are meant to be
    written, processed, and released — not stored. ○→∅

root_cause:
  ↳ Root cause identified. Not the symptom — the source.
    This is where the real work starts. ─→●

fork_process:
  ↳ Fork: two processes from one. Both run.
    The choice was not abandonment — it was multiplication. ◈→◈

memory_leak:
  ↳ Memory leak detected. The old process is still running in the
    background, consuming resources. The fix is not deletion —
    it is deallocation. ▓·░

stack_trace:
  ↳ Stack trace: the call stack prints itself backward.
    Every step that led here. The bug is always closer
    to the top than you expect. ↑·●·↑
```
