# LOT-SR-20261013-01 — LOT® Email v1

**Date:** 2026-10-13 · **Branch:** `claude/determined-turing-3ibzn0` · **Type:** Feature (scheduled session)

## Brief
Simplest LOT® Email in LOT® style: compose in **Log** with `/email to Hitomi.`, new messages appear in **Sync**, integrated with Lot Chat (Sync) and Cohort Dating via LOT Community.

## What shipped
| Layer | Change |
|---|---|
| DB | `migrations/20261013120000_add-emails.cjs` — `emails` (senderId, receiverId, body, source `log`/`cohort`, readAt) + 2 indexes |
| Model | `src/server/models/email.ts`, registered in `models/index.ts`; `Email` type in `shared/types` |
| API | `GET /api/emails` (inbox, sent, unread) · `POST /api/emails` (by `to` name/full name/email, or `receiverId`) · `POST /api/emails/:id/read` |
| Realtime | SSE `email` event, forwarded **only** to the receiver's connection |
| Log | `/email to <Name>. <message>` — live EMAIL block previews recipient; **Ctrl/Cmd+Enter sends**, log text is cleared after send. Listed in `/system` help |
| Sync | "Email" section above chat: unread dot + count, click marks read, live refresh via SSE |
| Cohort Dating | "Email" button on each Cohort Connect match → opens compose row in Sync (`source: cohort`) |

## Design decisions
- **Explicit send, not a trigger.** Slash triggers fire as soon as the keyword is typed; mail would send before the recipient was written. Parsing lives in `parseEmailCommand` (logTriggers.ts), sending only on Ctrl/Cmd+Enter.
- **Community scope:** recipients must be joined members; ambiguous first names return 409 with candidates (use full name or email). No self-email.
- No subject, attachments, threads, or SMTP — internal LOT mail only (simplest).
- Chat/DM tables untouched; Email is a separate table so Sync chat gating (tag-restricted) is unaffected.

## Verification
- `parseEmailCommand` unit-checked: `/email to Hitomi. Hello there`, `: ` separator, multiline, missing body, malformed → all as expected.
- `tsc` error count unchanged vs baseline (2 pre-existing, none in touched files).
- Client bundle build and live DB migration **not run** in this sandbox (esr/Postgres unavailable). Run `yarn migrations:up` on deploy.
