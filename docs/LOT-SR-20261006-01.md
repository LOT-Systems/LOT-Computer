## 4. MONK-LIFESTYLE / LOT AI TRANSPARENCY CHECK

- Positive: `/silent`, `/prayer`, `/night`, `/freeze` triggers exist; `WidgetErrorBoundary` shows an honest "Failed to load. Retry".
- **Finding M-1**: all ~41 widgets render on day 1 for any paid user; only *spacing density* adapts. This contradicts a
  monastic "one thing at a time" principle. See §6.
- **Finding M-2**: `/freeze` (`freeze-widgets`) trigger exists but widgets do not consult a shared "frozen" flag
  (only `Logs.tsx` and `logTriggers.ts` reference it; no widget consults a flag) — verify handler in `Logs.tsx` actually pauses timers/refetches.
- **Finding M-3**: Subscribe block (System.tsx ~921–941) uses `Math.random() < 0.2` **inside render** + `localStorage` reads
  in render. It is dead code in the pro layout (paid users have `hasSubscription`), but is non-deterministic if ever reached.
  Not transparent/idempotent — recommend `useState(() => Math.random() < 0.2)`.

## 8. WIDGET USAGE DATA LOG — **IMPLEMENTED (client-side v1)**

`WidgetErrorBoundary` now keeps a persistent per-widget ledger in `localStorage['lot.widgetLedger.v1']`:

```
{ "<WidgetName>": { mounts, crashes, retries, lastMountMs, maxMountMs, lastSeen } }
```

- Writes coalesced into one save per 2 s; all storage access in try/catch.
- Read from console: `__LOT_WIDGET_LEDGER__()`; programmatic: `getWidgetLedger()`.
- Covers all 25 boundary instances (Memory, Game, MonthlyPulse, Recipe, Pulse, Context, Bioethics, Check-in, Self-care,
  Intentions, Subscribe, Community, Planning, Cosmic Update, Quantum Sign, Flash Drive, Investor, Quantum Engine Connect,
  Biofield Engine, Dashboard, Architect, Stats, Calendar, Benchmark).
- **Limit:** counts *mounts and crashes*, not *interactions*, and is per-browser. Platform-wide aggregation needs a
  server endpoint (e.g. batch `POST /api/widget-ledger` daily from the client) — deferred, needs schema/privacy sign-off.
