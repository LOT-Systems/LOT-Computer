## DESIGN
```
ALERT TIMELINE (timed)   T-60 → T-15 → T-00 (NOW) → MISS (+15 min, until ACK)
ALERT TIMELINE (all-day) DAY at 08:00 local, same-day only in panel
CATCH-UP SAFETY          Tab asleep / late load → only the LATEST due stage fires, never a burst
STALENESS                Stages >24h old never fire; >2h old show in panel but are not re-logged/notified
EXACTLY-ONCE             Fired stages persisted as `calendar_alert` logs (cross-reload, cross-device)
                         + in-memory ref to cover refetch latency. Scheduler waits for log history.
ACK                      `calendar_done` log; entry leaves Upcoming, panel clears, MISS suppressed
DELIVERY CHANNELS        1) in-widget alert row (▲ T-15 MIN · CALL · 14:30 … ACK; pulses at NOW/MISS)
                         2) Log entry `[ALERT] …` 3) short square-wave tone (1 beep; 2 at NOW/MISS)
                         4) browser Notification, only after user taps "Enable alerts"
                            (never auto-prompts; button hidden once decided)
UI                       Minimalist preserved: no new panels/colors; one tiny time field
                         (HH:MM, lenient: 9, 930, 9:30) beside the text field; invalid time highlights border
```

## OPEN ITEMS / RISKS
```
1. Manual UI verification in a running app (alerts, ACK, notification permission flow).
2. /api/logs returns only the newest 500 logs; alert/ack logs (up to 5 per timed entry) consume
   that window — long-horizon entries could scroll out. Candidate fix: dedicated
   /api/calendar endpoint or exempt calendar_* events from the limit.
3. Two open devices can both fire a stage before either log is refetched (duplicate alert log,
   harmless). Candidate fix: server-side idempotency key on (entryId, stage).
4. Alerts only fire while the app is open (client-side). True background delivery would
   need a server scheduled job or Web Push.
5. Edit/delete of an entry and recurring events not yet implemented.
6. Intention-engine signal (recordCalendarSignal) does not yet carry time-of-day.
```
