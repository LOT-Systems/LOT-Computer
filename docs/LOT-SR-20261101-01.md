## 2. Fix shipped in this push

**`QuantumRandomWidget.tsx`** — two instances of `useQuantumNumber` each ran a 1 s interval, plus a 10 s interval, with no visibility gating:
- Each tick called `setState`, so a mounted-but-hidden widget re-rendered about 2×/s on other tabs and in background tabs.
- Each countdown rollover called `recordSignal('calculator','quantum_random')`, so **QIE received signals while nobody was observing**. That conflicts with the "no synthetic data" rule in `selfAssembly.ts`.

Change: ticks are skipped unless `!document.hidden && isRouteActive('system')`, the same pattern already used in SystemPulse, Chakra, ContextualPrompts and SystemProgress. Countdowns pause while hidden and resume on return.

Not yet confirmed: that the file builds and that the pause/resume behaves as intended. Please run the build before merging.

## 3. Lag and loading findings (not fixed, ranked)

1. **Eager bundle.** `System.tsx` (1071 lines) statically imports ~45 widgets. `SystemProgressWidget.tsx` alone is 2513 lines, most of it a changelog string table. Recommendation: `React.lazy` + `Suspense` for investor widgets (AngelInvestor, CorporatePlan, DemoDay), the heavy ones (SystemProgress, MicroGame, PatternRecognition, Integrity) and anything below the fold. Move the SystemProgress changelog to a JSON file fetched on demand. Measure first with `client:js:build:metafile`.
2. **TimeWidget** ticks every 1 s for chime checks. The tick is cheap and doesn't set state, but it never pauses. The `visibilitychange` catch-up is already in place, so it could be 15–30 s while hidden.
3. **MicroCalculator** polls every 10 s without gating. It is cheap, but it is the same pattern as item 2.
4. **Logs.tsx** is 4506 lines. Not a widget, but every widget log post lands there. Check list virtualization.
5. **Sound.** `sound.ts`, `sovietChime.ts`, `sovietGameSounds.ts` and `sovietKeyboard.ts` exist. 8 widgets use sound (MicroGame 36 refs, SelfCareMoments 8, CosmicUpdate 5). No central latency probe exists. `utils/perf.ts` observes INP (>200 ms warn) and long frames (>50 ms) but **only `console.warn`s and never reports**.

**Suggested lag test plan** (needs a browser, run in CI or locally):
- Playwright: for each System-tab widget, click through its buttons and record `performance.now()` deltas to the next paint.
- Drain `perf.ts` `interactions[]` and assert 0 entries >200 ms.
- Audio: measure `AudioContext.resume()` to first-sample latency after a tap.
- Tab switch: count React commits on hidden widgets (expected 0 after this fix).

## 5. Context sync and "military self-care" Log post (design proposal, nothing built)

No SITREP-style helper exists in the code. Proposal for any interactive widget:

```
postSitrep(widgetId, action, ctx)  →  POST /api/logs
  DTG   : 011430ZNOV26          (UTC date-time group)
  WIDGET: memory | planner | ...
  ACT   : answered | set | dismissed
  CTX   : weather, local time, users online   (already in System.tsx state)
  STATE : QIE phase / circadian phase (getCircadianPhase)
```

Principles for the monk-style design: terse, factual, one line per action, no inferred data (a missing context field is `N/A`), and LOT® AI only reads and reflects the log and never writes entries on the user's behalf.

## 6. 15-month month-to-month UI reveal

The documented reveal system (`docs/technical/INTERFACE_EVOLUTION.md`) is **achievement/level-gated** (Level 5, 10, 15, 25, 30, badge tier, etc.) and not calendar-gated. A grep for a 15-month schedule in `src/` found nothing relevant. The only "15" hits were a demo humidity formula and tier price text in About.

Gap: there is no month-1 to month-15 manifest saying which widgets appear when. Proposal: add `docs/technical/UI-REVEAL-15M.md` plus a `revealMonth` field per widget, and combine it with the existing level gates (`shouldShowWidget`). This needs a product decision from S-2 on the month-to-widget mapping before it can be built.
