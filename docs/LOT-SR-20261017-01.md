## FINDINGS THAT CHANGE THE PLAN

```
G1  No usership start date exists. MonthlyPulse and the monthly email count
    months from joinedAt, so an upgrade in month 7 would show "Month 7" on
    paid day 1. A usershipStartedAt field is the first dependency.
G2  Weekly LOT® AI Story (J24) is write-only: metadata.weeklyStory is saved
    but no component reads it. The weekly compression is never delivered.
G3  weeklyStory is overwritten each Sunday; the LOG endpoint caps at 500
    rows. Chapters need their own durable archive.
G4  MonthlyPulse dismissal is per-device localStorage (Cross-Device Sync).
G5  System.tsx treats R&D and Usership identically; no month awareness.
G6  Layout density has no calendar floor; a new account can land denser
    than "breathable".
G7  MonthlyPulse month 3 promises "Active User status", which does not exist.
G8  Monthly email starts at month 3; months 1-2 are silent.
G9  Demo profile is one frozen Year-4+ snapshot; cannot show a 12-month arc.
G10 Process: badge docs must ship with award logic (cf. SR-20260805-01).
```
