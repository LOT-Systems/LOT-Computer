## DESIGN — SIMPLEST THING THAT WORKS

LOT Email = the existing `DirectMessage` table, addressed **by name**.
- **Zero schema change, zero migration.** No new table, no new column.
- One message = sender, receiver, body (≤2000 chars). No subject/attachments/CC (deliberately cut).
- Unread state is per-browser (localStorage `lot:mail:seen`) — avoids a migration.

## FLOW

1. In **Log**, type `/email to Hitomi. Dinner at 8?` (also `/mail`, `/email Hitomi: …`, `First_Last` for two-word names).
2. An **EMAIL:** card appears under the editor: `TO HITOMI` + preview + **Send**. Nothing is sent until Send is pressed (Log autosaves while typing, so send-on-detect would misfire). Body stays in the log entry as normal.
3. Server resolves first name (case-insensitive; excludes self). Multiple matches → 409 with candidates ("use First_Last"). None → 404.
4. Message is stored, emitted over SSE to sender+receiver only.
5. **Sync** shows a **MAIL · N NEW** block above chat (latest 8 in/out, ● = unread). Click = mark read + open the reply thread (`/dm/:userId`).
