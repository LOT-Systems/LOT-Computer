## DESIGN — SIMPLEST POSSIBLE

```
ENVELOPE   = one DirectMessage row (senderId, receiverId, message)
COMPOSE    = Log entry containing "/email to <Name>"; body = lines after it
ADDRESS    = first name (optional last name) resolved inside LOT Community
DELIVERY   = SSE 'direct_message' sent only to the sender and the receiver
READ       = Sync → EMAIL block (latest envelope per correspondent) → /dm/:id
RECEIPT    = after Send, the command line in the Log is replaced with
             "✉ LOT Email → Hitomi Tanaka · 14:32", so it can't fire twice
```

### Syntax

```
/email to Hitomi
Hello Hitomi,
dinner on Friday?

/email to Hitomi Tanaka: one-line body
/email Hitomi                       ("to" is optional, a trailing "." is ignored)
```

Text above the command line stays private in the Log. Only the text below it, or after the `:`, is sent.

## SURFACES

| Surface | Change |
|---|---|
| **Log** | `LotEmailCompose` block (`EMAIL:`) appears while the entry contains the command. It shows rows for TO, BODY (N chars) and ROUTE (LOG → SYNC, with THREAD OPEN if the two have written before), plus a **Send** button. If several people share the name, they show as choices to pick from. `/system` help lists `/email to Name`. |
| **Sync (Lot Chat)** | `LotEmailInbox` block sits above the chat. It shows up to 7 correspondents, newest first, with `→` on outgoing messages and `●` on new incoming ones, and refreshes live over SSE. Clicking a row opens the existing `DirectMessageThread`. Users without chat access still see their inbox. |
| **Cohort Dating** | In `CohortConnectWidget`, "Send message" is now **Email**. It puts `/email to <First Last>` into the primary Log and routes to Log. If the match has no name, it falls back to `/dm/:userId`. |
| **LOT Community** | Only joined members who are not suspended can be found as recipients. Exact first-name matches rank first, then people you have written to before, then the most recently seen. At most 5 candidates are returned. |

## SERVER — NEW ENDPOINTS (`/api`)

```
GET  /email/recipients?q=Hitomi  → { recipients[ id, firstName, lastName, city,
                                     country, known, exact ] }   (min 2 chars)
POST /email { receiverId | to, message }
                                  → creates DirectMessage, emits SSE, logs
                                    'direct_message_sent' {channel:'email'}
                                    409 + candidates when "to" is ambiguous
                                    404 if self / not joined / suspended
GET  /email/inbox                 → { inbox[ userId, name, message, isMine,
                                     count, createdAt ] }  (20 threads max)
SSE  case 'direct_message'        → forwarded only to the sender and the receiver
```

**Side fix:** the SSE stream used to drop `direct_message` events completely, so the existing `/dm/:userId` thread never updated live. It now receives them, and only the two participants do.

## NOTES / NEXT

1. **Recipient lookup exposure.** Any signed-in member can look up another member's full name and city by typing a 2-letter first-name prefix. The Cohort widget already shows the same data. If this should be tighter, limit lookups to cohort matches plus existing correspondents.
2. **No outbound SMTP yet.** Envelopes stay inside LOT. The next step could be a Resend notification ("New LOT Email from X — open Sync") using `src/utils/email.ts`, gated by a setting.
3. **Unread state is per-session (`●`).** A persistent `readAt` column would need a migration, which this simplest version left out on purpose.
4. **`/dm/:userId` now updates live** because of the SSE fix. Check it once in staging.
