## DESIGN (simplest thing that works)

- **In-system mail only.** No SMTP / Resend / inbound parsing. Mail is a row in
  `mail_messages`; delivery = SSE push + inbox query. (Real outbound email is a
  later, optional layer — see Next.)
- **Compose = a Log slash command.** `/email to Hitomi.` — the closing period
  commits the recipient, so half-typed names never fire. Parsed by
  `parseEmailCommand()` in `logTriggers.ts` (new trigger `email-compose`).
- **A `MAIL:` block opens under the log**: `TO` line (resolved name), one body
  field, SEND. Ambiguous names show buttons; no match shows `NO MATCH`.
- **Receive = Sync.** A `MAIL` section sits above the chat: ● unread marker,
  sender, body, time, Reply. Click marks read. Live via SSE `mail_message`.
- **Audience = Sync audience** (Admin / R&D / Usership / Onyx / Legacy; Suspended
  excluded) for both sender and recipient, because mail is delivered into Sync.

## INTEGRATION


## API

```
GET  /api/mail/recipients?q=   prefix match first/last name, max 5, self excluded
GET  /api/mail                 inbox, newest first, max 50
POST /api/mail                 {recipientId, body(≤2000), source}  → SSE to recipient only
POST /api/mail/:id/read        recipient only
```
SSE `mail_message` is filtered server-side to `recipientId === req.user.id`.
Sends are logged as Log event `mail_sent` (metadata only, no body).
