## 1. Product definition
A 40 × 40 × 5 mm stainless "pager" that receives autonomous notifications from LOT-Systems.com (e.g. "Coffee time!"), shows them on a small screen, can photograph, senses weather/air, and sends a **Copy** button press back to the site's **Log** tab. Charges wirelessly.

- Side A: polished mirror stainless (316L) — silver flat square.
- Side B: camera + screen + button.
- 2-part stainless body.

## 2. CRITICAL feasibility findings (decide before ordering)
| # | Issue | Why | Recommendation |
|---|---|---|---|
| 1 | **Wireless charging cannot pass through stainless steel** (eddy currents) | Req 17/19 conflict | Put a non-metal inlay (ceramic/PEEK/glass, ~20 mm disc) in the polished back; coil + ferrite behind it. Or use the screen-side glass window (displaces display). Inlay is the brand-compatible choice: black ceramic disc on mirror steel. |
| 2 | **Wi-Fi/BLE antenna blocked by metal** | Faraday effect | Antenna of ESP32-S3-MINI-1 at an edge under a non-metal (glass/PEEK) split line; or use a plastic gasket ring between the two shells (also gives the 2-part seam). |
| 3 | **5 mm total height is extremely tight** | Steel walls 0.8 mm x2 → ~3.4 mm internal; camera module alone ≈ 3–4.5 mm | EVT target 40×40×**7 mm**; DVT attempts 5–6 mm with bare camera sensor on flex and 3.0 mm cell. Keep 5 mm as design goal, 7 mm as fallback. |
| 4 | Battery life | ~60–100 mAh cell | Deep-sleep pager: wake poll every 60 s, ~2–4 days; camera/Wi-Fi bursts only on demand. Wireless charge nightly. |
| 5 | Compliance | Radio + Li-ion | FCC Part 15 / CE-RED (pre-scan with module cert, final scan needed with steel), UN38.3 for cell, RoHS. Budget $8–15k. |
| 6 | Sensor vents | Weather sensor needs air | 0.6 mm vent hole + hydrophobic membrane on the screen-side shell. |

## 3. Architecture
```
LOT-Systems.com (Node/Fastify)  <--HTTPS/WSS-->  LOT-HW (ESP32-S3)
  /api/live-message  -> notification text           screen (ST7789 240x240)
  /api/weather       -> city weather               BME688 local T/RH/P/VOC (AI gas)
  POST /api/logs     <- "Copy" button event         BMI270 tap/motion, VEML7700 light
  POST /api/device/* <- photo, sensor (NEW)         OV2640 camera, Qi RX + LiPo
```
Layers: (1) hardware, (2) firmware (ESP-IDF, FreeRTOS, OTA), (3) LOT API connector, (4) host software (flasher/provisioning CLI), (5) manuals.

## 4. LOT API connector (req 6, 16)
Existing endpoints in `src/server/routes/api.ts`: `GET /live-message` (L820), `GET /weather` (L1038), `POST /logs` (L1563; body `{text, event, metadata}`). They use session-user auth.
Needed (Session 2 build, not done here):
1. `DeviceToken` model + `POST /api/device/pair` (6-char code shown on screen, confirmed in Settings).
2. Bearer-token auth for `/api/device/*` (scoped: read notifications, write logs/sensors/photo).
3. `GET /api/device/notifications?since=` (long-poll/ETag; payload ≤ 160 bytes, "compressed" per req 8: `{id,t,txt,ttl}`).
4. Button → `POST /api/logs {text:<current notification>, event:"device_copy", metadata:{deviceId, fw, battery, ts}}` so it appears in the Log tab.
5. `POST /api/device/telemetry` (temp/RH/pressure/VOC/battery) every 15 min; `POST /api/device/photo` (JPEG ≤ 60 KB) on demand.
6. Admin/AI trigger: scheduled job (`scheduled-jobs.ts`) generates autonomous notifications ("Coffee time!") from user context + weather and enqueues them.
