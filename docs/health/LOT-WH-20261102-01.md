## 3. Load-speed optimisation (✅ shipped)

Initial `app.js` contained every widget, including `SystemProgressWidget` (**177 KB**, mostly static changelog
strings) which sits far below the fold.

* `SystemProgressWidget` and `ArchitectWidget` are now `React.lazy` + `LazyMount` (viewport-deferred) + `Suspense`.
  They share one deferred chunk because `ArchitectWidget` imports `USERSHIP_TRANSMISSION` from
  `SystemProgressWidget` — that constant was **deliberately left in place** because the assembly protocol
  (`docs/assembly/*`) appends to it there.
* **Measured (esbuild, production):** `app.js` 729,837 B → 532,061 B.

Biggest remaining items in the app graph (minified KB): `badges.ts` 207 · `intentionEngine.ts` 140 ·
`Logs.tsx` 121 · `react-dom` 127 · `easter-eggs.ts` 24. **Next candidates:** lazy-load `badges.ts` (only needed on
unlock checks), `easter-eggs.ts`, and `Logs.tsx` sub-editors; split the changelog data out of `SystemProgressWidget` into JSON fetched on demand.

## 4. Wiring map

* **System tab (`System.tsx`):** 39 widgets mounted in grouped `WidgetErrorBoundary` stacks (Planning, Community, Bioethics, Biofield Engine, Dashboard, Stats…). `MemoryWidget` appears twice in source but in mutually exclusive branches (free vs paid) — not a double mount.
* **LOT® AI / QIE:** `recordSignal()` feeds `intentionEngine` (7-day retention, max-signal cap, persist deferred via `schedulePersist`, analysis deferred via `deferHeavy`). 20 of 39 widgets emit signals; **19 do not** (AIFeedback, AngelInvestor, Architect, Benchmark, CorporatePlan, CorrelatedIndexes, Cosmic, DemoDay, Evolution, Integrity, InterfaceEvolution, MonthlyPulse, PatternRecognition, QuantumSign, QuantumState, SignalStream, Subscribe, SystemPulse, Time) — mostly display-only, but interactive ones (QuantumSign, AIFeedback, MonthlyPulse dismiss, Subscribe click) are invisible to QIE.
* **Portrait / profile:** `/api/user-profile`, `/api/public/profile/:id` exist server-side and are consumed by `PublicProfile`; `PublicProfile.tsx` reads `streak`/`version` fields missing from its response type (4 type errors) — verify at runtime.
* **Memory & Story:** `MemoryWidget` → `GET /api/memory`, `POST /api/memory/answer`, `GET /api/memory/story` all resolve to server routes. `useCreateMemory` now typed with `insight`.
* **Endpoint audit:** 69 distinct `/api/*` paths referenced by the client were cross-checked against server routes. **One orphan:** `GET /api/export/all-logs` is advertised in `ApiPage.tsx:62` but **no server route exists** (404). Either implement or remove the card.
* **Log posting:** only `CalendarWidget`, `PlannerWidget`, `RecipeWidget` create Log entries directly. The `/ai-scan` Log trigger (`Logs.tsx` ~4002) already builds a military-format status block (CONNECTED · operators online/total · assembly % · badges · QIE patterns · last signal) — the right template for the SITREP proposal in §8.

## 5. Timers, sounds, controls

* 13 files use `setInterval`; all clear on unmount. Visibility-gated: SystemPulse (10 s poll, hidden-tab + route aware), ChakraErgonomics, ContextualPrompts, MicroGame (viewport), SystemProgress.
* ⚠ **Not gated** (re-render every second even when tab hidden / off-screen): `QuantumRandomWidget` (2 × 1 s `setState` ticks + 10 s toggle) — recommend `document.hidden` guard. `TimeWidget` 1 s tick only compares the hour (no setState) — fine; chime catch-up on `visibilitychange` present.
* `MicroCalculatorWidget` 10 s poll for the "magic time" — cheap.
* Audio: contexts are created lazily and `resume()`d on user gesture (`sovietChime`, `sovietKeyboard`, `sovietGameSounds`, `sound.ts`); no autoplay violations found in code.
* Side effect in render: `System.tsx` Intentions block writes `localStorage` (`intentions-last-shown`) **during render**, so the next render can hide the widget (cooldown just reset). Needs moving into an effect — flagged, not changed (behaviour decision).

## 8. Roadmap items from the brief (design, not yet built)

1. **15-month reveal (Digital UX routine):** today the interface evolves by achievements/streak (`interfaceEvolution.ts`); there is **no month index**. With `joinedAt` now exposed, add `monthNumber` (0–15) to the evolution store and gate widget groups month-by-month. Proposed schedule — M0 Time/Weather/Memory · M1 Planner/Recipe · M2 Intentions/Calculator · M3 Pattern Insights/Contextual · M4 Narrative/Goal Journey · M5 Chakra/Interventions · M6 Cohort-Connect/Chat Catalyst · M7 Quantum State/Signal Stream · M8 Pattern Recognition/AI Feedback · M9 Correlated Indexes/User Metrics · M10 Evolution/Interface Evolution · M11 Integrity · M12 Quantum Engine Connect · M13 System Progress/Pulse · M14 Architect · M15 full instrument density. *(Needs owner sign-off before implementation.)*
2. **Widget SITREP → Log ("military self-care"):** a shared `widgetContext()` (weather, local time, users online, QIE state) + a `/sitrep` Log trigger modelled on `/ai-scan`; interactive widgets (Planner, Recipe, Calendar already post) get a one-tap "post to Log" using that frame.
3. **Monk-lifestyle mode with LOT® AI:** a quiet-hours/`pure` density preset (fewer widgets, no sound autoplay, QIE directive-only) driven by the existing `$layoutDensity` store.
4. **Widget usage data log:** add `recordWidgetUse(widget, action)` → batched `POST /api/widget-usage` → aggregated per widget/day (server table or JSON log), feeding `/api/stats`. Currently signals are client-local (7-day, capped) so platform-wide usage cannot be reconstructed.
